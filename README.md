## v2.11.0 修了什么（重点）

这一版是架构化重构，核心是修掉「选了专用模型/备用模型就超时、还不生效」这个问题。
两个互相独立的根因：

**1. 专用/备用模型根本没被解析到。**
旧代码用 `context.get_provider()`、`context.providers`、`context.get_providers()`
三个入口找模型 —— 这三个在 AstrBot 4.x 里**都不存在**。所以只要在下拉框里选了模型，
解析必然失败，插件静默退回内置日程模板；而「不选」时走的 `context.get_using_provider()`
是真实 API，所以只有全局默认模型能用。现在改用真实 API
（`get_provider_by_id` / `get_all_providers`），并且失败时会在日志里直接列出所有可用 ID。

**2. 日程生成挂在聊天关键路径上，最坏阻塞约 184 秒。**
旧代码在 `on_llm_request` 钩子里同步生成日程，3 轮 × 60 秒超时；AstrBot 内联 await
这个钩子且没有超时保护，这些时间全额变成「发了消息没有回复」。而且默认 15 分钟粒度
要求模型一次输出约 96 个时段（5min 档 288 个），慢一点的模型根本吐不完。
现在读日程完全同步（缺失就先用内置模板），生成全部走后台单飞任务，
并且改为要求 8~16 个合并后的活动块。

**另外修掉的确定性缺陷：**

| 问题 | 说明 |
|------|------|
| 每次重载都泄漏后台任务 | 清理逻辑写在 `cleanup()`，而 AstrBot 的钩子叫 `terminate()`，从来没被调用过。改配置 N 次就有 N 个循环任务抢写同一个 state.json |
| `environment_mode` 是死配置 | 调用了 `AstrMessageEvent` 上不存在的 `is_group()` / `is_private()`，还被 `hasattr` 包着，所以永不过滤 |
| 跨天精力被瞬间拉满 | 跨天后把计费起点写成当天 00:00，于是第一条消息按「从午夜到现在」计费，凌晨两点后必然顶到上限 |
| 每条消息同步写盘 3~7 次 | 现在合并为每 5 秒一次，且写盘不占用事件循环 |
| `mood_affection_delta_cap` 可被突破约 2 倍 | 旧代码先钳制再乘精力/周期系数，现在钳制放到最后 |
| 情绪衰减每条消息遍历全表并持锁 | 改为每用户独立记账，消息路径只处理当前用户 |
| `/叫我`、`/查看所有昵称` 会丢数据 | 它们会把内存状态从磁盘整份覆盖回来 |
| `admin_qq` 无视 AstrBot 管理员 | 现在 AstrBot 管理员开箱即用 |
| 天气请求内联在消息路径 | 失败时最坏给回复加 20 秒；现在改后台刷新 + 读缓存 |
| `energy_natural_recovery_interval_minutes` 从未被读取 | 调它没有任何效果，现已真正接上 |
| 版本号四处不一致 | 收敛为单一来源 |

**新增：`/拟人诊断`**（管理员）—— 一条指令回答「为什么我的专用模型不工作」：
列出全部可用 Provider ID、首选/备用的解析结果、本次实际会用哪个、上次生成的失败原因、
冷却状态、今日日程来源。

## 它是什么

- 每天有不一样的日程安排（由大模型生成，后台生成不阻塞聊天）
- 精力会随着活动消耗和恢复（工作时段只减不加，休息时段才恢复）
- 有生理周期（6 个阶段，描述只提能量水平）
- 情绪会随着对话变化（好感度、亲近欲、攻击性）
- 会记住你让它生气的时刻（情绪日志）
- 天气会影响它的状态（接入 OpenWeather）
- 知道今天是星期几，知道你所在城市的当前时间
- 你可以设定它对你的称呼
- 心情标签（如"疲惫但开心"），直观显示当前情绪
- 社交能量（影响回复热情，长时间对话会消耗）
- 夜间睡眠模式（深夜回复变短或主动提示休息）
- 节日感知（内置公历节日 + 用户自定义）
- 支持首选模型 + 备用模型 + 全局默认的三级回退，失败模型自动冷却

## 模型选择逻辑

```
首选模型 (schedule_provider_name)
   ├─ 未找到 / 调用超时 / 调用报错 ──┐
                                     ▼
备用模型 (schedule_fallback_provider_name)
   ├─ 同样三种失败 ──────────────────┐
                                     ▼
全局默认模型 (schedule_allow_global_fallback，默认开启)
   └─ 失败 ──────────────────────────┐
                                     ▼
内置日程模板（按日期确定性轮换，永远可用）
```

- **三种失败等价**：v2.10.2 只有「未找到」才切备用，超时和报错不切。现在都切。
- **失败冷却**：失败的模型进入冷却期（默认 30 分钟）不再重试，避免每次生成都白等一轮超时。
  成功一次立即解除；`/重置日程` 会绕过冷却。
- **日程永不缺失**：整条链都失败时用内置模板，聊天照常进行。

配错 ID 时看哪里：日志里会直接打出 `你填的是 X，当前可用 id: [A, B, C]`，
或者直接 `/拟人诊断`。

## 关键配置项

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `schedule_provider_name` | 空 | 生成日程的首选模型（下拉选择，存 Provider ID） |
| `schedule_fallback_provider_name` | 空 | 备用模型 |
| `schedule_allow_global_fallback` | `true` | 是否允许回退到全局默认模型 |
| `schedule_llm_timeout_seconds` | 60 | 单次生成超时（v2.10.2 硬编码为 60 且不可调） |
| `schedule_generation_max_attempts` | 2 | 每个模型尝试几次 |
| `schedule_max_slots` | 16 | 时段数量上限，直接决定模型输出体积 |
| `schedule_provider_cooldown_minutes` | 30 | 失败模型的冷却分钟数，0 = 不冷却 |
| `schedule_time_granularity` | `15min` | 时间点对齐粒度（不再决定切多少段） |
| `mood_provider_name` | 空 | 情绪分析专用模型，留空沿用日程链 |
| `state_flush_interval_seconds` | 5 | 状态文件合并写盘间隔 |
| `weather_api_key` | 空 | OpenWeather API Key |
| `timezone_city` | `河源（记得改~）` | 时区城市，同时作为 AI 感知的所在城市 |

其余配置项见 `_conf_schema.json`（每一项都带 WebUI 说明）。

**从 v2.10.x 升级**：配置键与 `state.json` 完全兼容，直接覆盖即可，无需任何手动操作。
唯一的一次性变更是把 `schedule_allow_global_fallback` 从关改为开（会在日志里明确说明）——
如果你确实想禁止回退以控制成本，在插件配置里重新关掉即可。

## 代码结构

```
main.py                  # AstrBot 适配层：指令注册 + 事件解包 + HTTP 注入（约 370 行）
humanoid/
  config.py              # 唯一的默认值来源 + 类型强制 + 范围钳制
  state.py               # StateStore：异步锁 + 去抖原子写 + 字段迁移
  clock.py               # 时区 / 当前时间 / 星期 / 节日
  llm.py                 # ProviderResolver + LLMGateway（回退链 + 冷却熔断）
  slots.py               # 日程时段的解析与规范化流水线
  jsonx.py               # 从模型回复里抠 JSON（跳过字符串内的括号）
  prompt.py              # 注入文本构建
  diagnostics.py         # /拟人诊断 报告
  engine.py              # 编排层：服务装配 + 后台任务 + 指令文本
  services/              # schedule / energy / mood / social / weather
  data/                  # 城市时区表 / 节日 / 情绪映射 / 日程模板
tests/                   # 纯 stdlib unittest，不引入新依赖
```

`humanoid/` 子包不 import 任何 astrbot 模块，框架对象一律注入，所以整套业务逻辑
可以脱离 AstrBot 单测。被 `@filter` 装饰的处理器必须留在 `main.py`
（AstrBot 按 `handler.__module__` 查 `star_map`）。

跑测试：

```bash
python -m unittest discover -v
```

## 支持的城市

涵盖中国所有地级市（406 个条目）、俄罗斯主要城市及日本主要城市。

## 获取 OpenWeather API Key

1. 访问 [OpenWeather](https://openweathermap.org/) 注册账号
2. 在 API Keys 页面生成免费密钥：https://home.openweathermap.org/api_keys
3. 将密钥填入配置项 `weather_api_key`
4. 设置 `weather_location` 为城市英文名加国家代码，如 `Beijing,CN`
