# Humanoid Core - 拟真生活状态引擎 (v2.11.0)

一个有自己的时间、会累会恢复、情绪会积累的 AI 生活引擎。
联系作者：3881756548（重度依赖用户反馈与建议）

## 它是什么

- 每天有不一样的日程安排，由大模型生成；生成在后台进行，不会拖慢聊天回复
- 精力随活动消耗与恢复：工作/外出时段只减不加，睡眠与休息时段才回升
- 有生理周期（6 个阶段，描述只提能量水平，不提具体症状）
- 情绪随对话变化：好感度、亲近欲、攻击性三个维度，各自有基线与衰减
- 会记住让它情绪波动的时刻（情绪日志）
- 天气会成为它日常状态的一部分（接入 OpenWeather）
- 知道今天是星期几、知道你所在城市的当前时间、知道今天是什么节日
- 你可以设定它对你的称呼
- 心情标签（如「疲惫但开心」），直观显示当前情绪
- 社交能量：每条消息消耗，长时间不聊天恢复，影响回复热情
- 夜间睡眠模式：深夜回复变短，或主动提示休息
- 三档注入程度，控制它"知道你多少状态"
- 私聊 / 群聊 / 全开都行，它会根据场景调整语气

## 日程是怎么来的

每天第一次需要日程时，插件在**后台**向模型请求一份当天安排；请求期间聊天照常，
用的是按日期确定性轮换的内置模板，拿到结果后自动替换。所以模型再慢也不会让你的
消息卡住。

模型按候选链依次尝试：

```
首选模型 (schedule_provider_name)
   ├─ 未找到 / 调用超时 / 调用报错 ──┐
                                     ▼
备用模型 (schedule_fallback_provider_name)
   ├─ 同样三种失败 ──────────────────┐
                                     ▼
全局默认模型 (schedule_allow_global_fallback 控制，默认开启)
   └─ 失败 ──────────────────────────┐
                                     ▼
内置日程模板（按日期轮换，永远可用）
```

几个行为值得知道：

- **三种失败等价**：找不到、超时、报错都会切下一个候选，不区别对待。
- **失败冷却**：失败的模型进入冷却期（默认 30 分钟）内被跳过，不会每次生成都白等
  一轮超时。成功一次立即解除。`/重置日程` 会绕过冷却。
- **失败退避**：整条链都失败后，至少隔一段时间才自动重试，避免持续不可用时反复空转。
- **日程永不缺失**：所有候选都失败就用内置模板，其余功能不受影响。

配错模型 ID 时不用猜：日志会直接打出「你填的是 X，当前可用 id: [A, B, C]」，
或者直接 `/拟人诊断`。下拉框存的是 Provider ID，手填时注意大小写与下划线。

## 精力是怎么变的

日程里每个时段带一个 `energy_rate`（每分钟精力变化）。负值时段（工作、外出、社交）
只消耗；非负时段（睡眠、午休、休闲）才回升，自然恢复也只在这些时段生效。
生理周期会给消耗和恢复各自乘一个阶段系数。跨天时精力重置到 80 上下。

想让曲线更陡或更平，调 `energy_decay_rate`（全局速度倍率）和
`energy_natural_recovery_per_minute`（休息时段的额外恢复速度）。后者默认 0.9/分钟
偏快，睡一觉基本满值；想要更明显的起伏可以调到 0.1~0.2。

## 关键配置项

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `schedule_provider_name` | 空 | 生成日程的首选模型，下拉选择 |
| `schedule_fallback_provider_name` | 空 | 备用模型 |
| `schedule_allow_global_fallback` | `true` | 是否允许回退到全局默认模型 |
| `schedule_llm_timeout_seconds` | 60 | 单次生成超时 |
| `schedule_generation_max_attempts` | 2 | 每个模型尝试几次 |
| `schedule_max_slots` | 16 | 时段数量上限，直接决定模型要输出多少内容 |
| `schedule_provider_cooldown_minutes` | 30 | 失败模型的冷却分钟数，0 = 不冷却 |
| `schedule_time_granularity` | `15min` | 时段起止时间对齐到哪个刻度 |
| `use_llm_schedule` | `true` | 关掉就只用内置模板，完全不调模型 |
| `mood_use_llm_for_delta` | `false` | 是否用模型分析每句话的情绪变化 |
| `mood_provider_name` | 空 | 情绪分析专用模型，留空沿用日程链 |
| `inject_activity_context` | `low` | 注入程度：`full` / `low` / `mood_only` |
| `environment_mode` | `both` | 生效范围：全部 / 仅私聊 / 仅群聊 |
| `timezone_city` | `河源（记得改~）` | 时区城市，同时是 AI 感知的所在城市 |
| `weather_api_key` | 空 | OpenWeather API Key |
| `state_flush_interval_seconds` | 5 | 状态文件的合并写盘间隔 |

完整列表见 `_conf_schema.json`，每一项在 WebUI 里都带说明。

## 从 v2.10.x 升级

配置键与 `state.json` 完全兼容，直接覆盖即可，昵称、好感度、情绪日志都不会丢。

唯一的一次性变更：`schedule_allow_global_fallback` 默认从关改为开，并会写进你已有的
配置文件（启动日志里有一条 INFO 说明）。如果你确实想禁止回退以控制成本，在插件配置
里重新关掉即可。

## 代码结构

```
main.py                  # AstrBot 适配层：指令注册 + 事件解包 + HTTP 注入
humanoid/
  config.py              # 唯一的默认值来源 + 类型强制 + 范围钳制
  state.py               # StateStore：异步锁 + 去抖原子写 + 字段迁移
  clock.py               # 时区 / 当前时间 / 星期 / 节日
  llm.py                 # ProviderResolver + LLMGateway（回退链 + 冷却熔断）
  slots.py               # 日程时段的解析与规范化流水线
  jsonx.py               # 从模型回复里抠 JSON
  prompt.py              # 注入文本构建
  diagnostics.py         # /拟人诊断 报告
  engine.py              # 编排层：服务装配 + 后台任务 + 指令文本
  services/              # schedule / energy / mood / social / weather
  data/                  # 城市时区表 / 节日 / 情绪映射 / 日程模板
tests/                   # 纯 stdlib unittest，不引入运行时依赖
```

`humanoid/` 子包不 import 任何 astrbot 模块，框架对象一律注入，所以整套业务逻辑
可以脱离 AstrBot 单测。被 `@filter` 装饰的处理器必须留在 `main.py`——AstrBot 按
`handler.__module__` 查 `star_map`，放到子模块里会注册不上。

跑测试（在插件根目录）：

```bash
python -m unittest discover
```

## 支持的城市

涵盖中国所有地级市、俄罗斯主要城市及日本主要城市，共 406 个条目。

## 获取 OpenWeather API Key

1. 访问 [OpenWeather](https://openweathermap.org/) 注册账号
2. 在 API Keys 页面生成免费密钥：https://home.openweathermap.org/api_keys
3. 将密钥填入配置项 `weather_api_key`
4. 设置 `weather_location` 为城市英文名加国家代码，如 `Beijing,CN`
