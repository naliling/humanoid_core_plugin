# Humanoid Core · 人形化伴侣插件

一个有自己的时间、会累会饿会犯困、情绪会积累也会放不下的 AI 身体引擎。

**这个插件负责给 AI 一具身体，不负责替 AI 说话、思考、或者决定她回复多长。** 它把她的
身体与一天算出来、记下来，但往聊天上下文里放的只有**客观事实**（现在几点、隔了多久没说话、
怎么称呼对方）——写进去的句子模型不会当参考，只会当任务。说什么、说不说、说多长，都是
她自己判断（要不要主动开口交给
[自主拟人社交](#她与自主拟人社交是什么关系) 那个插件）。

---

## 它是什么

**身体（生理层 soma）**——一组会随时间自行变化的量，不只是一个「精力」标量：

- **睡眠压力**：醒着就一直攒，睡着才消解；生物钟低谷时段攒得更快
- **睡眠债**：该睡的时候醒着就欠下，靠睡觉还；欠着的时候第二天精力起点更低
- **昼夜节律**：凌晨是主低谷，午后有次低谷，傍晚最清醒——不是「23 点后算夜里」这种硬窗口
- **精力**：由日程时段驱动（工作/外出只减，睡眠/休息才回升），并被身体封顶
- **唤醒度**：与精力是两根轴。「很累但精神还有点亢、安静不下来」是可能的状态
- **饥饿**：距上次进食越久越饿；日程里写着用餐的时段会把这一顿吃掉
- **躯体不适**：久坐的肩颈发僵、天气的冷与热、生理周期的坠痛，合成一句「身上不太舒服」
- **社交能量 / 想找人说说话**：前者是聊累了，后者是独处攒出来的心思

时间自己流动：插件有一个每 60 秒一次的身体 tick，**不依赖有没有人发消息**。没人聊天的
那十几个小时里她照样会困、会饿、会坐太久。停机几天后重启，会按离线时长把身体补算回来
（上限 72 小时，不会攒出离谱数值）。

**心境与关系**

- 好感度、亲近欲、攻击性三个维度，各自有基线与衰减，随对话变化
- 好感度、亲近欲、攻击性偏到一定程度会**改变她的行为**（主动开口的意愿、想说话的程度、
  契约里给社交层的倾向），但 v2.16 起不再被翻成句子塞进上下文——那等于插件替她决定怎么开口
- 心情标签（如「有点疲惫，开心，亲切」）显示在 `/情绪详情` 里给人看，不进上下文
- 情绪日志：记住让她情绪波动的时刻
- 过程历史：刚做完什么，会作为「最近做过」提供给模型
- 对方离开前说的最后一句话，隔了一阵回来时能接得上
- **隔一段时间采样对方说过的原话**（默认至少隔 30 分钟一条、最多留 4 条），注入成
  「TA之前说过『我猫今天吐了，带去医院看了一下』，这些还没听TA说完下文」。不做关键词
  抽取：中文没有分词库时，它会把「我最近在准备考研」切成「考研」这种没法用的碎片

**生活与环境**

- 每天有不一样的日程，由大模型按**她在 AstrBot 里那份人格设定**在后台生成；生成期间用按
  日期轮换的内置模板，不卡聊天（v2.15 起不再用插件里那个十二选一的「角色人格」下拉）
- 持续进行的生活过程 + 过程内部阶段（一个几十分钟的过程里也会自然换小动作）
- 天气（OpenWeather）、时区/星期/节日、可设定的称呼
- 多角色完全隔离：每个机器人一份独立的身体、日程、心境，以及**每个角色独立的用户昵称表**
- 三档上下文 `full` / `low` / `mood_only`：只决定**给多少事实**，不给任何指导句（v2.16 起）

## 她与「自主拟人社交」是什么关系

| | 人形化伴侣插件（这里） | 自主拟人社交 |
|---|---|---|
| 管什么 | 她此刻是什么样：身体、心境、日程、天气、和谁的关系 | 现在该不该开口、找谁、说什么更像人 |
| 会不会主动发消息 | **不会** | 会 |
| 数据流向 | 导出契约快照 | 读契约，写回信号 |

两个插件一起用时不需要额外配置：

- **Core → Social**：`state.json` 里每个角色的 `self.contract`，带 `v` 版本号，字段只加
  不改。里面是各条身体轴、第一人称体感短句、说话形式倾向（`max_chars`、提问倾向）、
  她那个城市的 UTC 偏移（`time.utc_offset_minutes` / `time.tz`），以及「她多想找人说话」
  这个量。社交层拿它当念头模型的燃料，而不是自己从精力标量硬猜。
- **Social → Core**：社交层往**自己**的目录里写一个 `humanoid_signals.json`（刚主动找过
  谁、被连着冷落几次）。Core 只读它，超过 15 分钟不采信。两边各写各的文件，不存在两个
  插件抢写同一个文件的问题。

拿不到契约时（没装社交层、或 Core 太老没有 contract 段），社交层会退回读旧字段，功能
不中断。`/拟人诊断` 会明确告诉你联动到底有没有生效。

## 上下文里到底放什么：只有事实

这个插件给 AI 一具身体，不替她说话、不替她思考、不替她决定回复多长。落到实现上就是一句话：
**往聊天上下文里塞的只能是客观事实，不能是句子形的指令。**

写进去的「参考」，模型不会当参考，只会当任务。所以 v2.16 把注入层里这些东西全部删掉了：

| 删掉的东西 | 为什么 |
|---|---|
| 体感句（「眼皮很沉，句子不想写长」） | 那是插件替她把感受说出来，她只会照抄 |
| 话的份量（「这一轮只说一两句，控制在20字」） | 她在睡觉也不该被要求「必须 20 字以内」；插件拦不住回复，写规矩只是让模型猜 |
| 夜间语气（含「回一句我要睡了」的台词） | 她睡着时被吵到要怎么回是她自己的事；`night_mode_force_sleep` 整项删除 |
| 情绪态度句与语气表（「说话会短、会顶回去」「语气柔和，略带撒娇」） | 情绪该驱动她的行为与契约，不该被翻成句子塞给她 |
| 行为倾向（`compute_agency`：更主动、更好奇） | 直接就是调度口吻 |
| 边界句与许可句（「上面这些是你的身体……你自己定」） | 这类元指令本身就是噪声：事实不需要免责声明 |
| `UTC+08:00`、百分比、数值 | 给人看的东西不该进她的嘴 |

现在默认档（`low`）的全部内容就这么多：

```
【时间】2026-09-15 星期二 21:40 晚上；你在上海；这是私聊。
【称呼】你管TA叫小鱼
【刚刚】距上次说话 3 小时 12 分；TA上一句说的是「我猫今天吐了」
```

`full` 档再加几块生活事实（也都是名词性的，不带任何"所以你要怎样"）：

```
【今天】今天到这会：上午在改第三季度的海报、中午在午餐与午休；现在在跟客户过方案；傍晚还要通勤与买菜。
【TA说过】TA之前说过「我猫今天吐了，带去医院看了一下」
【天气】这边小雨，气温 12℃
```

`mood_only` 档只给一个关系档位词（`对TA的感觉：在意`）。

那身体和生活去哪了？**它们仍在算，只是不进上下文**：

- `state.json` 里存着各条身体轴、情绪三轴、今日日程、过程与天气；
- 联动契约把它们导出给「自主拟人社交」，那边决定要不要开口、说什么；
- `/你的状态`、`/查看日程`、`/好感度`、`/拟人诊断` 给人看；
- 她自己的表现（累不累、想不想说话、说多长）由模型从「晚上九点四十分」「她刚跑完一整天」
  这些事实里自己幻想出来——**这才是拟人，不是靠提示词硬塞**。

测试看着这一条：`tests/test_v216_facts.py` 把身体推到极端（熟睡、饿、难受、被冷落）后渲染
三档上下文，断言里面没有命令式句子、没有体感句、没有字数要求，也没有斜杠地名与偏移量。

## 升级（覆盖安装）

AstrBot 的「本地安装 zip」不会覆盖同名目录：装过旧版时直接上传会报
`安装失败：目录 astrbot_plugin_humanoid_core 已存在。`，插件列表里的「更新」也只会报
`该插件不是通过插件市场安装，无法检测或执行更新。`（上传安装的插件没有市场来源）。
升级二选一，两种都不丢身体状态：

1. 面板：插件 → 本插件 → 卸载（**不要勾**「删除配置」「删除数据」）→ 立即上传新 zip。
   配置在 `data/config/astrbot_plugin_humanoid_core_config.json`，身体与日程状态在
   `data/plugin_data/humanoid_core/state.json`，卸载只删 `data/plugins/<目录名>`，两个都不动。
2. 终端原地替换：先把新 zip 用「本地安装」上传一次（会失败，但包已落到
   `data/temp/plugin_upload_<原文件名>`），再解压覆盖 `data/plugins/astrbot_plugin_humanoid_core`，
   最后在面板点「重载」。

升级后第一次启动会看到日志里的配置默认值迁移提示：AstrBot 只补缺失键、从不覆盖已有值，
所以没手动改过、但停在旧版默认值上的项由插件自己提升一次。

## 日程是怎么来的（v2.15：按她是谁来排）

以前 prompt 开头是 `请为「温柔体贴」这个人设，规划今天一整天的生活日程`——一个插件里的
十二选一标签。形容词排不出一天：没有职业、没有住处、没有来往的人，于是日程永远是
「上午工作、中午午餐、下午工作」这种谁看了都不会信是自己过的东西。

现在直接读**她在 AstrBot 里生效的那份人格设定**（会话上指定的 → 该会话配置画像的默认 →
全局默认，解析链与正常聊天完全一致），让她是谁先立住，再排她的一天：

```
她是「林小满」。下面是她在 AstrBot 里的人格设定，这就是她本人，不是她在扮谁：
<人设原文，按行边界截到 1200 字>

先从这里读出她的身份、年纪感、职业或在读状态、住在哪里、独居还是跟人住、平时跟谁来往、
喜欢什么讨厌什么、花钱和精力的习惯。
设定里没写的，按最合理的方式补一个出来，然后每天都沿用同一个答案：这份日程每天都会重排，
但同一天里她不能今天在读大学、明天在上班。
```

几个必须说清的点：

- **按角色隔离，插件里不放全局人格开关**。AstrBot 的 `unified_msg_origin` 第一段就是平台
  适配器实例，配置画像按 `platform_id::` 路由，所以按角色记账过的会话来源解析人格，天然
  就是按角色隔离的——一个机器人接多个人设、多个角色各用人设都自动正确。
- **代表会话从消息里记账**（`roles[bid].self.last_umo`），重启后也能立刻恢复。角色刚创建、
  还没收到过任何消息时取全局默认人格。
- **认出人设后会把今天重排一次**（每角色每人设每天最多一次）。不加这一手，插件刚装好那天
  的日程会一直停在「没见到人设」的版本上，要等到半夜跨天才对得上。
- `[%None]`（该会话显式不用人格）按「没有人设」处理，**不会**回退到默认人格——含义相反。
- 读不到人设时 prompt 走一段中性身份（「一个有自己生活的普通人」），日程照生成，不会因此
  停摆。想彻底关掉：`schedule_use_persona=false`。
- `schedule_prompt_extra` 保留，但它现在是**补充**而不是唯一依据。

每天第一次需要日程时，插件在**后台**向模型请求一份当天安排；请求期间聊天照常，用的是
按日期确定性轮换的内置模板，拿到结果后自动替换。

候选链：`首选模型 → 备用模型 → 全局默认模型 → 内置日程模板`。找不到、超时、报错三种
失败等价处理；失败的模型进入冷却期（默认 30 分钟）内被跳过，成功一次立即解除；整条链
都失败则按退避间隔重试。**日程生成失败不会阻止第二天重新尝试。**

一个值得知道的细节：**失败退避以前会被永久绕过**——`today_date` 只在生成成功时写入，
模型一直不可用时它永远不是今天，于是每个后台周期都被当成「跨天」而绕过冷却，变成每
30 秒一次永久重试。v2.14 起会记住「今天试过」，退避真正生效。

## 身体是怎么变的

日程里每个时段带一个 `energy_rate`（每分钟精力变化）。负值时段只减，非负时段才回升；
生理周期给消耗和恢复各乘一个阶段系数。此外：

- **睡眠债**压低新一天的精力起点（欠得越多起得越低，最低到 5 折）
- **躯体不适**放大消耗、并给精力设一个当天封顶——欠着一身债的人，就算日程写着整个
  下午都在休息也回不满
- **吃饭**由日程里的用餐时段决定，一顿就把饥饿归零
- **久坐**在日程写着运动/通勤/家务的时段会被打断
- **天气**的冷热计入躯体不适（需要天气可用）

想调曲线：`energy_decay_rate`（全局速度倍率）、`energy_natural_recovery_per_minute`
（休息时段的额外恢复）、`sleep_need_hours`、`meal_interval_hours`、
`sitting_discomfort_minutes`、`desire_refill_hours`。

## 作息：夜间窗口、日程、一晚睡多久

「她几点起」以前有三个地方都能回答，而它们互相不认识：夜间窗口说 5 点，日程模板说
7:30，`sleep_need_hours` 说 8 小时（而且根本没人读它）。v2.14.2 把三者接成一条链：

| 层 | 管什么 | 不管什么 |
|---|---|---|
| `night_start_hour` → `night_end_hour` | **生物钟夜**：入睡点与起床点、昼夜低谷的位置、睡眠债的记账边界、夜间语气 | 不直接决定她此刻在不在睡 |
| 今日日程的睡眠段 | **她实际在睡的那几个小时**（`is_sleep_time` 只认事件名） | —— |
| `sleep_need_hours` | 一晚睡多久算睡饱：困意清除速率 = `100/本值` 每小时；熬夜欠的债按 `本值/窗口长度` 放大 | 不再参与醒来时的记账 |

两边由 **`schedule_follow_night_window`**（默认开）对齐：日程 prompt 里写清她几点上床、
几点起，模型不听话时安装前还会把睡眠区间按夜间窗口重切一次，内置模板同样对齐。所以
把 `night_end_hour` 设成 6，她 6 点就真的已经起了床。

窗口比 `sleep_need_hours` 短（例如 23:00→05:00 配 8 小时）是**真的会出问题的配置**：
一夜睡不满，早上带着没清完的困意起床，下午就蔫。`/拟人诊断` 的【作息】会直接标出来，
想睡够 8 小时就把起床点推到 07:00。

**夜间不再往上下文里注入任何东西**（v2.16）。以前这里有「夜间语气」两档，还会在深睡时
直接给出「我现在需要休息，明天再聊吧」这句台词让模型照着发；配置项 `night_mode_force_sleep`
已整个删除。她在睡觉时被人找来要怎么回，是她自己的判断——插件既拦不住回复，也不该替她说。

夜间窗口本身仍然有用，但那是**身体**的事：睡眠债从几点开始记、昼夜低谷摆在哪、日程该
几点让她上床。关掉 `night_mode_enabled` 意味着不再记睡眠债、昼夜低谷失去位置，而且
**没有日程时她永远不算在睡**。

`form_policy`（她此刻大概说多长、想不想问）照旧计算并写进联动契约——社交层的主动消息靠它
决定长度，但聊天回复不受它约束。

## 上次对话间隔

`last_interaction_threshold_minutes` 默认 5 分钟：超过这个时间，插件才开始在上下文里
注入间隔信息。算的是**上一次触发回复**到现在，所以纯指令消息和没唤醒它的群消息不会
重置计时。第一次对话没有历史，不会出现这段提示。

`last_interaction_mode` 两档（v2.14 起真的区分）：

| 模式 | 行为 |
|---|---|
| `simple` | 只说「距上次说话 3 小时 12 分」这样一个准确时长 |
| `with_last_msg` | 同上，并附上 TA 离开前说的最后一句话（默认） |

v2.16 起这里给的是**准确时长**，不再是「对方隔了约 2～6 小时重新出现」这类档位话术——
那把一件客观事描述成了一种情境，模型会当成"该做点什么"的信号。

间隔事件是**一次性**的：只在「回来这一轮」出现，下一条用户消息开始就清掉，不会在一小时
里每条消息都重复注入。

## 情绪是怎么算的

好感度、亲近欲、攻击性三个维度，每条消息先过一遍本地词典规则；开着
`mood_use_llm_for_delta`（默认开）时，每 `mood_llm_interval_messages` 条消息（默认 5）
再叫模型分析一次，两个结果加权融合。计数从 0 起算，所以新面孔的第一条消息只走本地规则。

- 精力与生理周期会调制情绪变化的幅度（排卵期更敏感，经期正负都被放大）
- 心情标签在每次情绪更新时刷新（`mood_tag_enabled`），显示在 `/情绪详情` 里
- 群聊默认不参与情绪：`mood_enabled_in_group` 关着时群消息不做情绪分析与衰减，但发言过
  的成员仍会记录聊天间隔与上一条消息（群聊里的「知道好久没聊了」靠它）
- 情绪模型的失败冷却与日程的冷却各自记账，即使两边用同一个模型也互不影响
- `mood_data_retention_days` 默认 7 天：超过 7 天没说话的用户，情绪档案会被清掉，好感度
  回到初始值；**用户自己设定的昵称保留**。设为 0 = 永不清理

  persona.py             # 按角色解析 AstrBot 生效人格（日程生成用）+ PersonaSource 缓存
  recall.py              # 隔一段时间采样对方说过的原话（「记得」注入块）
  slots.py               # 日程时段的解析与规范化流水线
  link.py                # 与自主拟人社交的契约：导出 contract、只读 signals
  diagnostics.py         # /拟人诊断 报告
  engine.py              # 兼容层：路由到 RoleManager

  core_instance.py       # 单个角色的完整装配 + 后台循环
  services/
    soma.py              # 生理层：多轴稳态 + 耦合 + 离线补算
    schedule.py          # 每日日程（大模型 + 模板兜底）
    energy.py            # 精力与生理周期（由日程驱动，被身体封顶）
    mood.py              # 情绪三维度、基线、衰减、日志、心情标签、过期清理
    social.py            # 社交能量
    process.py           # 生活过程与内部阶段、过程历史
    behavior.py          # 短期事件、注意力、行为倾向
    weather.py           # 天气
  data/                  # 城市时区表 / 节日 / 情绪映射 / 日程模板
tests/                   # 纯 stdlib unittest，不引入运行时依赖

`humanoid/` 子包不 import 任何 astrbot 模块，框架对象一律注入，所以整套业务逻辑可以
脱离 AstrBot 单测。被 `@filter` 装饰的处理器必须留在 `main.py`——AstrBot 按
`handler.__module__` 查 `star_map`，放到子模块里会注册不上。

跑测试（在插件根目录）：

```bash
python -m unittest discover -s tests -t .
```

311 项，其中 24 项是 `main.py` 的集成测试。跑之前需要 `tzdata`（本容器没有
`/usr/share/zoneinfo`，`tests/fakes.py` 用 `zoneinfo` 会整模块 import 失败）：

```bash
pip install --target /tmp/pylibs tzdata && PYTHONPATH=/tmp/pylibs python -m unittest discover -s tests -t .
```

## Token 预算

两个插件加起来一共只有 4 处会真的调用模型，全部量过（注入器自己渲染真 prompt，不拿常量猜）：

| 调用点 | 什么时候发生 | 实测单次消耗 |
|---|---|---|
| 聊天时追加的上下文 | 每次聊天请求 | v2.16 只留事实：low 档 ≈36、full 档 ≈66、mood_only 档 ≈20 token（旧版是 260~310） |
| 日程生成 | 每角色每天 1~2 次 | 输入 ≈570（无）～1320（带人设，截到 1200 字）+ 输出按 16 时段 ≈550 |
| 情绪分析 | 每 5 条私聊 1 次（可关） | ≈520（用户消息只取前 500 字） |
| 社交层写话/把关 | 每次准备主动开口 | 生产最坏 ≈2100（含人设 800 字 + 5 条历史）；输入预算卡在 6000 token，超了按固定优先级丢块 |

卡住上限的几道：

- 上下文按档设硬上限（`low` 220 / `full` 620 / `mood_only` 60 字符，v2.16 把指导句删了所以
  收紧），**按块边界切**而不是按字硬截，不留半句话给模型去补。
- 人设原文按行边界截到 1200 字再进日程 prompt；日程一天最多生成两次（认出新人设时重排一次），
  不会因人格反复变动而无限重跑。
- `schedule_prompt_extra` 是自由文本配置项，截到 300 字（以前无界，粘一篇设定就能把日程
  请求撑大）。
- 天气/情绪没配好时给管理员看的说明书不再进模型上下文（以前会漏一句「把 weather_location
  填成英文名+国家码」）。
- 开 `debug_mode` 后，日志会直接打出本次注入的字符数与 token 估算。
- `/拟人诊断` 新增【Token 预算】段，用真状态量当前档实际多大，不是拿常量报数。

## 城市与时区：她按哪个钟过日子

`timezone_city` 不只是给 `/时间` 用的：她看到的钟点、日程里几点做什么、夜间窗口、睡眠债
从几点开始记、注入里那句「你在北京」、天气算不算得冷，全部按这个城市的当地时区算。

- **三个国家的地区全部收录**，共 723 条：中国 425（全部地级行政区＋省直辖县级＋港澳台）、
  俄罗斯 179（覆盖 27 个 IANA 时区里的每一个，85 个联邦主体的首府与主要城市）、
  日本 110（47 都道府县厅所在地与政令市）。表内条目都映射到真实 IANA 时区名，夏令时由
  IANA 数据自己处理。
- 这张表拿 GeoNames cities500 完整文件（235,808 行）逐条对过时区归属与覆盖率：人口≥1 万的
  中国城市只剩 9 个乡镇级重名条目未收，俄罗斯与日本零缺失；与 GeoNames 不一致的 28 条
  逐条有结论（新疆按北京时间是既定选择、汉德加以 IANA 自己的注释为准），其中 2 条按核对
  改正（滕达、比利比诺）。
- **表里没有的地方直接填 IANA 时区名**：`Asia/Ho_Chi_Minh`、`America/New_York`、
  `Europe/Berlin` 都能用（v2.15.1 起）。她说出来的是中文城市名（「你在伏尔加格勒」），
  不是 `Europe/Volgograd` 这种代码。
- **中国大陆（含新疆）统一按北京时间**：铁路、电视、手机都走北京时间，这是法定时区；
  真想让她按当地 UTC+6 过日子，把 `timezone_city` 填成 `Asia/Urumqi` 即可。
- **填错与缺库分开报**：名字拼错时说「这个时区名用不了（可能拼错了）」，机器缺 tzdata 时
  才说「装一份时区数据库」——两种情况的改法完全不同。
- **不再静默退化**。旧版在机器缺 tzdata 时会偷偷换成 `Asia/Shanghai`：设成东京的她其实
  按北京时间过一天，而注入里还写着「你在东京」，从聊天记录里根本看不出来。现在退化成
  AstrBot 这台机器的本地时间，并把原因说出来。
- **换城市会把旧账重新起算**。精力与天气的「上次更新」在 state.json 里存的是墙上时间，
  换个城市再拿新时区解释就会凭空多出几小时。现在角色创建时发现城市变了，就把这两项按
  新城市重新起算（日志里会说一句）。
- **去哪看有没有真生效**：`/拟人诊断` 的【时间与时区】给出城市 → 生效 IANA 名 → 她此刻
  的钟点，再与机器时间对比（差几个小时是预期的，一致而城市在另一个国家就是不预期）；
  认不出城市、缺 tzdata、城市还没定这三种情况都会带 ⚠ 与改法。`/时间` 的输出也带
  `UTC±HH:MM` 偏移，一眼能对上。

## 获取天气 OpenWeather 密钥

1. 访问 [OpenWeather](https://openweathermap.org/) 注册账号
2. 在 API Keys 页面生成免费密钥：https://home.openweathermap.org/api_keys
3. 将密钥填入配置项 `weather_api_key`
4. 把 `weather_location` 填成城市英文名加国家代码（如 `Beijing,CN`），或者留空让它
   跟随 `timezone_city`——但那样 `timezone_city` 本身就得是英文名
