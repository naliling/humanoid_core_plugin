# 人形化伴侣插件

一个为 AstrBot 设计的轻量级拟人化插件。它为 AI 角色提供身体状态、生活日程、情绪变化、人际关系和环境信息，让角色不仅有一份固定的人设，还能根据时间、近期互动和自身状态，形成更连贯的表现。

**核心定位**：插件负责维护角色的状态和生活背景，具体怎么说话、如何回应，仍然由大模型根据人设与对话自行决定。

## 一、主要功能

### 1. 身体与生理状态

为角色建立一套会随时间变化的身体状态，而不只是简单地记录一个精力数值。

包括：

- **精力与唤醒度**：根据休息、活动和身体负担变化，不同数值代表不同的状态。
- **睡眠系统**：记录睡眠压力、睡眠不足、刚醒的睡眠惯性，以及睡着时有没有被消息吵到。
- **饥饿与身体不适**：结合上次进食、久坐、天气以及其他生理因素，形成相应的身体状态。
- **生理周期**：模拟周期推进及不同阶段的身体感受，并影响部分状态变化。
- **社交能量**：记录角色在交流中的消耗，以及独处时逐渐恢复或积累的状态。

这些状态会随时间持续推进，不要求用户每隔一段时间发送消息才会更新。插件也会对停机期间的状态变化进行有限补算。

### 2. 动态日程与生活背景

角色的日程可以根据其人设、作息和当前身体状态动态生成，而不是每天机械地重复同一套固定安排。

日程采用分段方式管理，主要描述角色当前正在进行的活动。活动可以随时间和适当的事件发生变化，不必每天固定睡午觉、工作或休息。

- **凌晨也是完整的一天**：00:00–06:00 不是天然的睡觉时段。人设是夜猫子、夜班或白天补觉的人，凌晨可以排夜里的活动（出门、值班、打游戏、写东西、散步、吃夜宵）；早起型的人凌晨在睡则是正常的。插件会从人设里认出这些生活特质，认不出时按原来的默认语气排。
- **人设特质识别**：从人设正文里保守识别夜猫子 / 早起 / 勤快 / 懒散 / 宅 / 外向 / 倒班 / 学生 / 上班，日程语气与过程模板会跟着调整；不会因此替角色决定她「应该」是什么样的人。
- **睡眠与梦**：睡眠段会额外生成梦（普通夜里 2 条，白天睡的那一觉 3 条），契约会把它导出给社交插件，`/查看日程` 也能看到。刚醒的 30 分钟内，聊天上下文里可以出现一句「她刚从梦里醒过来」。
- **睡眠惯性、被吵醒与赖床**：消息不会掀被子（睡着的那一段不会因为来消息就重排），但会记下「被吵到」；刚醒的一小段时间里她还没完全缓过来，没急事时可以赖床、回笼觉。困意越线（80/100）时这一段会优先休息，不再排做饭、工作、出门这类要精神的事；白天困到越线时，本地兜底也会安排 45–90 分钟小睡。
- **可以中途被打断、也可以接着做下去**：私聊里隔一阵来找她、或者明确叫住她（「在吗」「你在干嘛」「陪我」这类），她会得到一次「要不要放下手上的事」的机会；被换成别的事之后，原来那件事会**挂起**一段时间（默认 3 小时），等她忙完可以自己回去接着做（生成时会看到「被打断之前她在做X，还剩Y分钟」）。另外还有两条明确的口子：`/拟人 日程打断` 让她立刻换一件事，`/拟人 日程继续` 把当前这一段直接往后延长。
- **打断的「保鲜期」可以调**：安静间隔、打断冷却、来访保鲜期、重事件保鲜期、挂起保留多久、一次续多久，全部有配置项（`schedule_interrupt_*`、`schedule_event_ttl_minutes`、`schedule_pause_ttl_minutes`、`schedule_continue_minutes`）；默认值与旧版写死的数值一致，升级当天行为不变。把安静间隔调成 0、或打开 `schedule_interrupt_on_call`，她对「你叫住她」会更敏感。

日程主要用于维护角色的生活背景，不会每轮都直接把完整日程塞进对话，要求角色照着复述。用户可以使用 `/查看日程` 查看当前安排。

如果启用大模型日程生成，角色的活动安排会更灵活；关闭后则使用内置日程方案。

### 3. 情绪与人际关系

插件会根据用户的互动维护角色的情绪与关系状态，包括：

- **好感度与亲近程度**：记录角色与不同用户之间的关系变化。
- **情绪变化**：根据互动情况调整心境，避免每条消息都把角色当成完全没有情绪历史的状态。
- **关系差异**：不同用户拥有各自的关系记录，不会把对一个人的态度直接套用到另一个人身上。
- **认识时长**：每轮上下文里会带一句「你们已经认识 N 天了」（不足一天说「你们刚认识不久」），让关系有厚度；它只是一句陈述事实，不要求角色时时提起。`/你的状态` 面板仍给准数与「个月/年」档。
- **注意力状态**：区分角色对某个人的在意程度、对当前话题的关注程度，以及自身剩余的注意力。
- **情绪恢复与积累**：部分情绪具有持续性，不会在下一条消息到来时立刻全部清零。

相关状态会以适合模型理解的自然语言提供给上下文，而不是要求模型直接复述好感度数值或一整份状态报告。

### 4. 时间、地区与天气

插件可以根据角色所在地区提供生活环境信息，包括：

- 当前时间、星期与时区。
- 日期、节日和季节等背景信息。
- 当地天气信息。
- 用户为角色设置的称呼与名称。

其中，角色所在地区会影响其使用的时间与作息。天气功能需要相应的 API 配置，其他基础时间信息不依赖天气服务。

### 5. 对话间隔与近期事件

角色可以获得适当的近期互动背景，例如用户上一条消息的内容，以及双方已经间隔了多久。

这些信息只是供模型判断是否需要接续话题、关心对方或者自然地转换话题，并不要求角色每次都询问用户去了哪里，也不会把时间间隔强制转换成固定问候语。

插件还会限制近期原话的使用范围，避免角色反复翻出很久以前的一句话，造成答非所问或不断重复旧话题。

### 6. 多角色与独立状态

在同一个 AstrBot 环境中，不同机器人角色可以拥有独立的身体状态、日程、情绪和关系数据。

每个角色根据自己的配置和人设运行，不会因为其他机器人更换日程、改变情绪或与用户互动，就直接覆盖自己的状态。

## 二、它如何影响 AI 的回复？

插件的作用不是直接替模型生成回复，而是把合适的信息提供给模型参考。

例如，角色可以知道自己最近休息得不好、当前心情受到之前互动的影响，或者与某位用户已经有一段时间没有交流。但这些信息不代表角色必须在下一句话中提到它们。

插件遵循以下原则：

- 提供状态背景，不强制生成指定台词。
- 不规定每条回复的固定字数或格式。
- 不要求角色每轮都报告自己的身体、情绪或日程。
- 不使用单一情绪标签决定整段回复的语气。
- 尽可能避免重复注入相同信息，减少上下文冗余。

插件提供的是角色能够参考的背景，而不是一套替角色决定所有行为的固定脚本。

## 三、与自主拟人社交插件的关系

两个插件的职责不同，可以配合使用。

| 对比 | 人形化伴侣插件 | 自主拟人社交插件 |
|---|---|---|
| 主要职责 | 维护角色的身体、情绪、日程和关系状态 | 决定是否主动联系用户，以及联系谁、聊什么 |
| 是否主动发送消息 | 不负责 | 负责 |
| 日程与状态 | 负责生成和维护 | 可读取相关信息作为决策参考 |
| 关系信息 | 维护基础关系状态 | 可结合关系与互动情况决定主动交流的时机 |

安装自主拟人社交插件后，可以通过两者之间的状态接口共享部分信息。没有安装社交插件时，人形化伴侣插件仍然可以独立运行。

两边同进程运行时走**门面**（按需现算、不读会过期的磁盘快照），拿不到门面才退回读 `state.json`。门面在 2.28.9 起除了身体/日程/未完成事项，还按人给一份**称呼与关系情境**：她认定的称呼（`/叫我` 设的、或自动认的）、TA 的名片名（`display_name`）、能直接叫出口的 `call_name`、好感与涨幅、情绪标签、TA 此刻的状态标签、在意度、认识多少天、最近说过的话、以及亲密状态。这样主动消息才能叫人、才知道这个人最近说过什么、该用多近的语气。名片名另外也写进 `state.json`（`roles.<bid>.users.<uid>.display_name`），老路径照样拿得到。

## 四、常用指令

以下为常用的状态查看和操作指令。

| 指令 | 作用 |
|---|---|
| `/你的状态` | 查看身体、精力、情绪、关系及相关状态 |
| `/亲密状态` | 查看她此刻的亲近欲、门槛与亲密场景状态（私聊） |
| `/查看日程` | 查看角色当前的日程安排 |
| `/时间 城市` | 查询指定城市的时间 |
| `/好感度` | 查看关系及好感度信息 |
| `/情绪详情` | 查看详细情绪状态 |
| `/情绪日志` | 查看情绪变化记录 |
| `/叫我 昵称` | 设置角色对自己的称呼 |
| `/拟人帮助` | 查看插件帮助 |

管理员还可以通过 `/拟人` 指令组执行日程重置、状态重置、情绪管理、配置调整及诊断等操作。具体指令以插件帮助为准。

## 五、安装与配置

插件适用于 AstrBot 4.x 环境，提供基础配置与进阶配置。

安装后建议先完成以下设置：

1. 设置角色所在城市或时区，确保时间、作息与地区背景正确。
2. 确认 AstrBot 中的角色人设已经配置好，日程与角色行为背景需要参考这份人设。
3. 根据需要启用大模型日程生成、情绪模型分析及天气功能。
4. 先使用默认配置运行，确认效果后再调整进阶项目。

插件的模型调用取决于启用的功能和对应的配置。关闭相应的模型功能后，可以使用本地规则或内置方案处理部分状态。

## 六、数据与功能边界

插件会保存运行所需的角色状态、日程和关系数据，以便重启后继续使用。

**长期记忆不归它管。** 它不会自行建立一套长期聊天记忆库，也不负责完整保存和检索用户的聊天历史。近期互动信息只用于有限的上下文辅助，不能代替专门的记忆系统。

它会留两样**短**东西：最近 12 小时内你说过的一句原话，以及**手上还开着的未完事项**——装了「自主拟人社交」时，对方提了没下文的、她答应过还没兑现的那些事会被记下来（最多三条、最多放三天，事情一了结就自动消失）。这两样都是随每条回复一起递给她的一句事实，**不落会话历史**：会话历史被压缩掉之后，它们还在。它记的是「有这么件事还开着」，不是那段对话的原文。

装了记忆插件（「我会牢牢记住你」）时，它会把两边接上：**读**——每轮按你刚说的那句话去检索这个人的长期记忆，压成一句事实并进同一个事实块；**写**——她自己生活里的事真正结束时补一条回去（那件事在聊天里看不见，只有她知道）。记忆插件一个字节都不用改，没装也照常跑，只是没有这一份。

## 总结

人形化伴侣插件的目标，是让 AI 角色拥有持续变化的身体状态、生活安排和情绪关系背景。

它负责维护这些信息，但不代替大模型进行完整的对话决策，也不负责主动聊天。通过适量、连续且有实际意义的状态信息，让角色在不同时间和不同互动对象面前，能够表现得更加自然和连贯。

## 多台 bot 同群时（FAQ）

**一、机器人认不出「另一台 bot」是它同类。**

多台 bot 在同一个群里时，**每台 bot 在事件层看起来就是普通群成员**——AstrBot 不会告诉插件
「这条是别的机器人说的」。本插件会把**本进程见过名字的其它角色**一并挡下：既不进消息合并，
也不触发回复、不记账（v2.27.7 起连「只混群、从没私聊过」的兄弟也认得出）。
但**跨 AstrBot 实例/跨容器的 bot 认不出**（各自一份状态、看不到对方），
那种情况只能靠：不要在同一个群放多台都装了本插件的 bot，或让它们各自少说话。

**二、机器人「不知道自己发过什么 / 把你和别的 bot 认混」——查这个开关。**

AstrBot 配置里有一项 `platform_settings.ignore_bot_self_message`（面板：「忽略机器人自己的消息」，
**默认关闭**）：

- **关闭（默认）**：部分平台（NapCat 等）会把机器人自己发出去的消息**回灌成一个消息事件**丢回给插件。
  本插件的消息合并层、身体记账层都已经会跳过 sender==自己的事件，不会「在等自己说话」。
- **开启**：机器人自己发的消息在**任何插件看到之前**就被框架丢弃（源码：waking_check 阶段直接
  `stop_event`）。消息记账仍靠发送侧钩子，多数情况不受影响；但它意味着插件**彻底看不到机器人自己的
  同一条消息以事件形式回来**。

什么时候该开它：平台上出现「机器人把自己刚说的话当新消息、自己回自己」的循环时。
平常保持默认（关闭）就好。如果你发现机器人「好像不知道它刚发过什么 / 把别的 bot 的发言当成你说的」
——先看这个开关和多 bot 部署，再看本插件。

## 状态是怎么交给模型的

1. **状态进用户消息，「怎么读它」与环境背景进 system_prompt。** 每轮在变的状态（她对 TA、心情、
   身体感觉）进用户消息；几点、天气、季节、她今天在做什么这些**背景**进 system_prompt——
   塞进用户消息模型会拿它们当开场白（「这边也是阴天」）。AstrBot 保存历史时存的是拼装后的
   用户消息，所以每次注入前会先把上下文里**旧的块抹掉**，全程只有一份、永远是新鲜的。
2. **给体感，不给数值。** `好感46.0/100`、`UTC+08:00` 是给人核对的体检单。要看数值去
   `/你的状态`、`/好感度`、`/拟人 诊断`。
3. **指代只有一个指向。** 词表里「她」= 这个角色、「TA」= 对话方，**不写「你」**（system_prompt 里
   「你」已经是角色了）。拼装完把「她」换成人设里的角色名（`/拟人 参照名称` 可指定），**只换第一次**
   ——名字是用来建立映射的，每句都以名字开头就成了流水账。框架句里会写明「XX 指你自己」。
4. **同一件事只说一遍。** 关系位置、心气、精力、想不想说话，各自有且只有一个来源。
5. **阈值高于配置初始值。** 否则「惦记TA」「拧巴」是常驻背景而不是异常信号。
6. **措辞按天抽签。** 程度由轴值挑，同一档位备 2~3 套说法，按（角色+今天+用户）抽签：同一天不把
   同一句话说两遍。
7. **元信息不进上下文。** 「认识多少天」只留在 `/你的状态` 面板——递进模型它就会拿去念。
8. **不替她说话，也不给她立规矩。** 这两条由 `tests/test_v2151_freedom.py` 把身体推到极端后逐项断言。

## 安装与升级

AstrBot「本地安装 zip」**不覆盖同名目录**。装过旧版要先卸载（**不要勾**「删除配置」「删除数据」），
再上传新 zip。配置在 `data/config/astrbot_plugin_humanoid_core_config.json`，身体状态在
`data/plugin_data/humanoid_core/state.json`，卸载两个都不动。

**装完第一件事：改「她所在的城市」**。它决定她的钟点、作息和天气城市；不改的话时区会静默退回服务器
所在时区，天气和季节也一起错掉。表里没有的城市可以直接填 IANA 时区名（`Asia/Ho_Chi_Minh`）。

依赖只有 `aiohttp`。

## 内部实现速查

**日程**：每 15 分钟一个决策窗，到点或掷中「改主意概率」才让模型排**下一段**（不预排未来）。
关掉模型时用按日期轮换的本地模板，同一时刻永远有段可做——静默不等于留白。
**有人打破一段安静来找她**（只看私聊：安静间隔/打断冷却都可配，默认 45 分钟 / 1 小时；私聊里
明确叫住她（「在吗/你在干嘛/陪我」，`schedule_interrupt_on_call`）不熬安静间隔也算）时，
给她一次中途换事/去干别的的机会（带动冷却与闸门，不会一条消息重排一次；消息不断的部署里
它自然很少触发）。**被打断的旧活会挂起**（`schedule_pause_ttl_minutes`，默认 3 小时）：
忙完可以自己回去接着做；`/拟人 日程打断` 强制换一件、`/拟人 日程继续` 直接延长当前段。
**睡眠不受消息打扰**，一觉睡到这段自然结束。
`schedule_max_slots` 真正生效（面板最高 96）：填多少就最多留多少段。
每次给模型的举例**按天轮换**（不再每天看到同一批）；每天第一次决定时顺带定一句
「今天大概是什么日子」，后续每段都带着它——这是治「每天都差不多」的两招。
她「此刻在做什么」就是当前日程段（早期那套独立的「过程/行为阶段」已退役）。

**身体**：睡眠债、久坐、饥饿按时间步长积分；被身体封顶（欠着觉时日程里写着休息也回不满）。停机后按
离线时长补算，上限 72 小时。

**作息**：夜间窗口是「几点算夜里」的生物钟，不等于她几点睡——几点睡由日程决定。生物钟低谷的时段
攒睡眠压力更快。

**情绪**：本地词典先判，模型结果只占 0.3 权重融合。**本地已经判负明确时那一次模型调用会被跳过**——
模型结果本来也会被丢弃，省掉是零代价。情绪只在收到消息时更新，没人说话它不变。

**上下文档位**：`mood_only` / `medium` / `full` 只决定给多少事实。真正卡住体积的是
`inject_token_budget`（默认 3500 token，正常用量远达不到它）。

**写盘**：状态变更后最多每 `state_flush_interval_seconds`（默认 60 秒）整份重写一次，原子替换。
体积随用户条目增长，`/拟人 诊断` 会显示文件大小与用户数。

## 城市与时区

她按 `timezone_city` 过的日子：`/时间 城市` 可以查别的城市，但**她的身体和日程只按这个**。
填「河源/北京/泽列诺格拉茨克」这类表里有的名字，或者直接填 IANA 时区名（`Europe/Moscow`）。
表里没有名字时会**静默退回服务器时区**——`/拟人 诊断` 的【时区】会直接告诉你有没有生效。

地名表覆盖 9,855 条：**中国**（地级 + 县级驻地 + 人口 ≥2 万的镇，含敦煌、满洲里、阳朔、婺源）、
**日本**（47 都道府县 + 县厅所在地 + 全部市町村）、**俄罗斯**（85 个联邦主体 + 全部首府 + 有中文名的
居民点）。写 `广东省`/`大阪市`/`東京都`/`北海道` 这类带后缀的也认，繁体与日文写法会自动转简体别名
（`軽井沢` = `轻井泽`）。**表里没有的地方直接填 IANA 时区名**，一定生效。

多 bot 可以在各自的 `/拟人 设置 城市` 里单独设，互不影响。

## 获取天气密钥

[OpenWeather](https://openweathermap.org/) 注册即送免费密钥，填进 `weather_api_key`。
天气城市填英文名+国家码（`Beijing,CN`）；留空则跟着 `timezone_city` 走（且必须是英文名）。
两处不一致会出现「说在北京却报河源的天气」。
