# Humanoid Core · 人形化伴侣插件

## 使用者的话

> 上一版的注入长这样：
>
> `…外头这边 [Zelenogradsk,RU] 天气：多云。她今天上午在起身去厨房准备水果和下午茶，现在在**坐在**客厅沙发上看书。她对TA热烈，她和TA十分在意，一股气没处发，有点惦记TA，你们认识几天了，刚才TA惹她不痛快了，她今天精神饱满，心情不错，矛盾。`
>
> 一个人，把「热烈」和「一股气没处发」放在同一句里；把「精神饱满」和「矛盾」放在同一句里；人设里的**示例对话**被当成她刚说过的话抽出来，每轮都带着。😭
>
> 为这个重做了两轮：每句话重新对过指代、阈值、重复与来源。细节看 [更新日志](CHANGELOG.md)。

## 简介

一个有自己的时间、会累会饿会犯困、情绪会积累也会放不下的 AI 身体引擎。

**这个插件负责给 AI 一具身体，不负责替 AI 说话。** 她的困、饿、攒着的火、今天过到这会干了什么，
都会真的进到上下文里让她感觉到；但它**不替她写台词**（「我现在需要休息，明天再聊吧」那种）、
**不给她下禁令**（「不要接着聊」「必须 20 字以内」——插件本来就拦不住回复）、
**不把体检单读数端给她**（好感 46.0/100、UTC+08:00）。说什么、说不说、说多长，是她自己的判断。

## 她有什么

**身体（生理层）**——一组会随时间自行变化的量，不只是一个「精力」标量：

| 量 | 怎么变的 |
|---|---|
| 睡眠压力 | 醒着就一直攒，睡着才消解；生物钟低谷时段攒得更快 |
| 睡眠债 | 该睡时醒着就欠下，靠睡觉还；欠着时第二天精力起点更低 |
| 昼夜节律 | 低谷摆在哪**按她今天日程里那段觉算**（夜猫子凌晨 4 点睡，低谷跟着挪） |
| 精力 | 由日程时段驱动（工作/外出只减，睡眠/休息才回升），并被身体封顶 |
| 唤醒度 | 与精力是**两根轴**。「很累但精神还有点亢、安静不下来」是可能的状态 |
| 饥饿 | 距上次进食越久越饿；日程里写着用餐的时段会把这一顿吃掉 |
| 躯体不适 | 久坐发僵 + 天气冷热 + 周期坠痛，合成一句「身上不太舒服」 |
| 社交能量 / 想找人说 | 前者聊累了会掉，后者独处时攒起来 |

时间自己流动：每 60 秒一次 tick，**不依赖有没有人发消息**。没人聊天的那十几个小时里她照样会困、
会饿、会坐太久。停机几天后重启会按离线时长补算回来（上限 72 小时，不会攒出离谱数值）。

**心境与关系**

- 好感度、亲近欲、攻击性三轴，各有基线与衰减，随对话变化
- **注意力三条轴**：`在意度`（对这个人，慢变量，每用户有自己的基线）、`上心程度`（对 TA 正在讲的
  这件事，每条现算）、`注意力余量`（她自己还剩多少）。进上下文的是措辞，数值在 `/你的状态` 里看
- 情绪会以**「（她的内心：心里有点堵）」**这样的形式进上下文——括号告诉模型这是隐藏状态、
  不是台词。措辞是日常话（「心里有点堵」），不是病历腔（「心里压着火」那种会被模型原样复读）
- 当天基调按日累计，一天之内不翻来覆去；「你上次的火她还没消」要**当天负向 ≥2 次或近 2 小时**才出现
  （单次不算——那叫记仇）
- 心情标签只显示在 `/情绪详情` 里给人看，**不进上下文**
- **隔一段时间采样对方说过的原话**，注入成「TA之前说过『我猫今天吐了』」。只给最近 12 小时内的一条：
  挂的是两天半前的话，模型会顺着翻旧账

**生活与环境**

- 日程由大模型按**她在 AstrBot 里那份人格设定**滚动分段决定（一次只排当前这一段），每隔 15 分钟按
  她当时的身体数值重排一次；生成期间用内置模板，不卡聊天
- 天气（OpenWeather）、时区/星期/节日、可设定的称呼
- 多角色完全隔离：每个机器人一份独立的身体、日程、心境与昵称表
- 三档上下文 `mood_only` / `medium`（默认）/ `full`：只决定**给多少事实**，三档都只给客观事实
- 间隔不是一句秒表读数：TA 那句原话 + 隔了多久，接不接由她自己判断

## 她与「自主拟人社交」的关系

| | 人形化伴侣（这里） | 自主拟人社交 |
|---|---|---|
| 管什么 | 她此刻是什么样：身体、心境、日程、天气、和谁的关系 | 现在该不该开口、找谁、说什么更像人 |
| 会不会主动发消息 | **不会** | 会 |
| 数据流向 | 导出带版本号的契约快照 | 读契约，写回信号 |

两个一起用不需要额外配置。**没装社交插件时这里的导出也无害。**
`/拟人 诊断` 的【联动】区块会直说到底接上没有：「已装但没写过信号文件」/「文件在但已 N 分钟没刷新」。

## 状态是怎么交给模型的

1. **事实进用户消息，「怎么读它」进 system_prompt。** 事实每条都在变；system_prompt 里那段说明不跟
   消息滚。AstrBot 保存历史时存的是拼装后的用户消息，所以每次注入前会先把上下文里**旧的块抹掉**，
   全程只有一份、永远是新鲜的。
2. **给体感，不给数值。** `好感46.0/100`、`UTC+08:00` 是给人核对的体检单。要看数值去
   `/你的状态`、`/好感度`、`/拟人 诊断`。
3. **指代只有一个指向。** 词表里「她」= 这个角色、「TA」= 对话方，**不写「你」**（system_prompt 里
   「你」已经是角色了）。拼装完把「她」换成人设里的角色名（`/拟人 参照名称` 可指定），**只换第一次**
   ——名字是用来建立映射的，每句都以名字开头就成了流水账。框架句里会写明「XX 指你自己」。
4. **同一件事只说一遍。** 关系位置、心气、精力、想不想说话，各自有且只有一个来源。
5. **阈值高于配置初始值。** 否则「惦记TA」「拧巴」是常驻背景而不是异常信号。
6. **措辞按天抽签。** 程度由轴值挑，同一档位备 2~3 套说法，按（角色+今天+用户）抽签：同一天不把
   同一句话说两遍。
7. **元信息不进上下文。** 「认识多少天」只留在 `/你的状态` 面板——递进模型它就会拿去念。
8. **不替她说话，也不给她立规矩。** 这两条由 `tests/test_v2151_freedom.py` 把身体推到极端后逐项断言。

## 安装与升级

AstrBot「本地安装 zip」**不覆盖同名目录**。装过旧版要先卸载（**不要勾**「删除配置」「删除数据」），
再上传新 zip。配置在 `data/config/astrbot_plugin_humanoid_core_config.json`，身体状态在
`data/plugin_data/humanoid_core/state.json`，卸载两个都不动。

**装完第一件事：改「她所在的城市」**。它决定她的钟点、作息和天气城市；不改的话时区会静默退回服务器
所在时区，天气和季节也一起错掉。表里没有的城市可以直接填 IANA 时区名（`Asia/Ho_Chi_Minh`）。

依赖只有 `aiohttp`。

## 指令

**查状态（谁都能用）——这 8 条直接打，不带任何前缀**

| 指令 | 作用 |
|---|---|
| `/你的状态` | 精力、身体轴、生理、天气、日程、关系、注意力（分六组列对齐） |
| `/查看日程` | 她今天过出来的日程（动态现排，不预排未来） |
| `/时间 城市` | 指定城市当前时间 |
| `/好感度` | 情绪档案总览 |
| `/情绪详情` | 含基线值与交互轮次 |
| `/情绪日志` | 情绪波动记录 |
| `/叫我 昵称` | 设置她对你的称呼（没设过时她会自动认一次，认过之后不再改） |
| `/拟人帮助` | 显示帮助 |

> 早期版本这 8 条是带前缀的，后来拆成两层：**常用的不带前缀，管理员的 10 条
> 才留在 `拟人` 组里**。下面几张表里带 `/拟人 ` 前缀的才是组内指令。

**管理员 · 改配置**

| 指令 | 作用 |
|---|---|
| `/拟人 设置` | 看常用项；`/拟人 设置 城市 大阪` 改一项，立即生效 |
| `/拟人 参照名称 名字` | 设定注入里代表她的名字（默认跟人设里的名字） |
| `/拟人 诊断` | 排查模型选择、时区是否生效、上下文多大、状态文件多大 |
| `/拟人 重载` | 重载插件配置（面板改完进阶项用它刷新） |

**管理员 · 动数据**

| 指令 | 作用 |
|---|---|
| `/拟人 重置日程` | 立即重新决定她当前这一段 |
| `/拟人 重置状态` | 重置精力、社交能量与生理周期 |
| `/拟人 重置情绪` | 把**你自己**的情绪重置到初始值 |
| `/拟人 设置好感度 数值` | 手动设置自己的好感度（0-100） |
| `/拟人 批量好感度 QQ:值,QQ:值` | 批量导入 |
| `/拟人 查看昵称` | 所有用户设置的昵称 |

## 关键配置项

面板上共 93 项，这里列真正需要动的：

| 项 | 默认 | 什么时候调 |
|---|---|---|
| `timezone_city` | 河源（占位） | **必改**。决定她的钟点、作息、天气、季节 |
| `她所在的角色人设` | AstrBot 那边设 | 日程按它排；写她的语气、身份、说话习惯 |
| `use_llm_schedule` | 开 | 关掉则日程改用本地模板（更省额度，情节也更死板） |
| `llm_daily_call_budget` | 200 | 每日模型调用**次数**上限（不是 token），多 bot 共享一份 |
| `llm_idle_silence_minutes` | 60 | 连续这么久没人说话就停掉后台调用，有人一说话立刻恢复 |
| `mood_use_llm_for_delta` | 开 | 关掉则情绪**完全本地**判断，零额外调用 |
| `mood_llm_interval_messages` | 5 | 每人每几条消息用模型分析一次情绪（**按人算**） |
| `mood_data_retention_days` | 7 | 超过这么多天没说话，情绪档案清回初始值（称呼保留） |
| `auto_identify_user` | 关 | 开则注入里用真名区分「她」和「对方」 |
| `auto_nickname` | 开 | 从消息自带的名字认一次称呼；含数字/emoji/占位词一律不认 |
| `weather_api_key` | 空 | OpenWeather 密钥（免费档就够） |
| `soma_enabled` | 开 | 关掉则只剩精力一个数 |

改完面板里的进阶项，用 `/拟人 重载` 刷新；`/拟人 设置` 改的项立即生效。

## 内部实现速查

**日程**：每 15 分钟一个决策窗，到点或掷中「改主意概率」才让模型排**下一段**（不预排未来）。
关掉模型时用按日期轮换的本地模板，同一时刻永远有段可做——静默不等于留白。

**身体**：睡眠债、久坐、饥饿按时间步长积分；被身体封顶（欠着觉时日程里写着休息也回不满）。停机后按
离线时长补算，上限 72 小时。

**作息**：夜间窗口是「几点算夜里」的生物钟，不等于她几点睡——几点睡由日程决定。生物钟低谷的时段
攒睡眠压力更快。

**情绪**：本地词典先判，模型结果只占 0.3 权重融合。**本地已经判负明确时那一次模型调用会被跳过**——
模型结果本来也会被丢弃，省掉是零代价。情绪只在收到消息时更新，没人说话它不变。

**上下文档位**：`mood_only` / `medium` / `full` 只决定给多少事实。真正卡住体积的是
`inject_token_budget`（默认 3500 token，正常用量远达不到它）。

**写盘**：状态变更后最多每 `state_flush_interval_seconds`（默认 5 秒）整份重写一次，原子替换。
体积随用户条目增长，`/拟人 诊断` 会显示文件大小与用户数。

  llm.py                 Provider 解析 + 网关（回退链、冷却、节流闸门）
  services/              schedule / mood / soma / energy / social / weather / behavior / process

  link.py                与社交层的契约

## 城市与时区

她按 `timezone_city` 过的日子：`/拟人 时间 城市` 可以查别的城市，但**她的身体和日程只按这个**。
填「河源/北京/泽列诺格拉茨克」这类表里有的名字，或者直接填 IANA 时区名（`Europe/Moscow`）。
表里没有名字时会**静默退回服务器时区**——`/拟人 诊断` 的【时区】会直接告诉你有没有生效。

地名表覆盖 9,855 条：**中国**（地级 + 县级驻地 + 人口 ≥2 万的镇，含敦煌、满洲里、阳朔、婺源）、
**日本**（47 都道府县 + 县厅所在地 + 全部市町村）、**俄罗斯**（85 个联邦主体 + 全部首府 + 有中文名的
居民点）。写 `广东省`/`大阪市`/`東京都`/`北海道` 这类带后缀的也认，繁体与日文写法会自动转简体别名
（`軽井沢` = `轻井泽`）。**表里没有的地方直接填 IANA 时区名**，一定生效。

多 bot 可以在各自的 `/拟人 设置 城市` 里单独设，互不影响。

## 获取天气密钥

[OpenWeather](https://openweathermap.org/) 注册即送免费密钥，填进 `weather_api_key`。
天气城市填英文名+国家码（`Beijing,CN`）；留空则跟着 `timezone_city` 走（且必须是英文名）。
两处不一致会出现「说在北京却报河源的天气」。
