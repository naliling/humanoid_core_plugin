# Humanoid Core · 人形化伴侣插件

一个有自己的时间、会累会饿会犯困、情绪会积累也会放不下的 AI 身体引擎。

**这个插件负责给 AI 一具身体，不负责替 AI 说话。** 她的困、饿、攒着的火、今天过到这会干了
什么，都会真的进到上下文里让她感觉到；但插件**不替她写台词**（「我现在需要休息，明天再聊吧」
那种）、**不给她下禁令**（「不要接着聊」「必须 20 字以内」——插件本来就拦不住回复）、
**不把体检单读数端给她**（好感 46.0/100、社交能量 100%、UTC+08:00）。说什么、说不说、
说多长，是她自己的判断（要不要主动开口交给
[自主拟人社交](#她与自主拟人社交是什么关系) 那个插件）。

---

## 它是什么

**身体（生理层 soma）**——一组会随时间自行变化的量，不只是一个「精力」标量：

- **睡眠压力**：醒着就一直攒，睡着才消解；生物钟低谷时段攒得更快
- **睡眠债**：该睡的时候醒着就欠下，靠睡觉还；欠着的时候第二天精力起点更低
- **昼夜节律**：低谷摆在哪**按她今天日程里那段觉算**（夜猫子凌晨 4 点睡，低谷就跟着挪），
  午后有次低谷——不是「23 点后算夜里」这种写死的窗口
- **精力**：由日程时段驱动（工作/外出只减，睡眠/休息才回升），并被身体封顶
- **唤醒度**：与精力是两根轴。「很累但精神还有点亢、安静不下来」是可能的状态
- **饥饿**：距上次进食越久越饿；日程里写着用餐的时段会把这一顿吃掉
- **躯体不适**：久坐的肩颈发僵、天气的冷与热、生理周期的坠痛，合成一句「身上不太舒服」
- **社交能量 / 想找人说说话**：前者是聊累了，后者是独处攒出来的心思

时间自己流动：插件有一个每 60 秒一次的身体 tick，**不依赖有没有人发消息**。没人聊天的
那十几个小时里她照样会困、会饿、会坐太久。停机几天后重启，会按离线时长把身体补算回来
（上限 72 小时，不会攒出离谱数值）。

**心境与关系**

- 好感度、亲近欲、攻击性三个维度，各自有基线与衰减，随对话变化
- **注意力三条轴**（v2.16.4）：`在意度`（对这个人，慢变量，每用户有自己的基线）、
  `上心程度`（对 TA 正在讲的这件事，每条现算）、`注意力余量`（她自己还剩多少，跟 TA 无关）。
  进上下文的是措辞，数值在 `/你的状态` 里看
- 情绪偏到一定程度会**改变她的行为**（主动开口的意愿、想说话的程度、契约里给社交层的倾向），
  并且会被说成她此刻的心气（「看TA有点不顺眼」）——但只说她心里怎么样，不写「所以说话要短、
  要顶回去」，那是插件替她决定怎么开口
- 心情标签（如「有点疲惫，开心，亲切」）显示在 `/情绪详情` 里给人看，不进上下文
- 情绪日志：记住让她情绪波动的时刻
- 过程历史：刚做完什么，会作为「最近做过」提供给模型
- 对方离开前说的最后一句话，隔了一阵回来时能接得上
- **隔一段时间采样对方说过的原话**（默认至少隔 30 分钟一条、最多留 4 条），注入成
  「TA之前说过『我猫今天吐了，带去医院看了一下』，这些还没听TA说完下文」。不做关键词
  抽取：中文没有分词库时，它会把「我最近在准备考研」切成「考研」这种没法用的碎片

**生活与环境**

- 日程由大模型按**她在 AstrBot 里那份人格设定**滚动分段决定（一次只排当前这一段），并且**每隔 15 分钟按她
  当时的身体数值（精力/饥饿/睡眠压力/睡眠债）重排一次**——不是一天排一次就定死；生成
  期间用按日期轮换的内置模板，不卡聊天（v2.15 起不再用插件里那个十二选一的「角色人格」下拉）
- 持续进行的生活过程 + 过程内部阶段（一个几十分钟的过程里也会自然换小动作）
- 天气（OpenWeather）、时区/星期/节日、可设定的称呼
- 多角色完全隔离：每个机器人一份独立的身体、日程、心境，以及**每个角色独立的用户昵称表**
- 三档上下文 `medium`（默认）/ `full` / `mood_only`：只决定**给多少事实**，三档都只给
  客观事实；到底多大看当时的身体与日程，`/拟人诊断` 的【Token 预算】拿真状态量给你看。
  「这些事实该怎么读」是一段固定的框架句，进 system_prompt，不跟着消息滚
- 间隔不是一句秒表读数：TA 那句原话 + 隔了多久，接不接、怎么接由她自己判断

## 她与「自主拟人社交」是什么关系

| | 人形化伴侣插件（这里） | 自主拟人社交 |
|---|---|---|
| 管什么 | 她此刻是什么样：身体、心境、日程、天气、和谁的关系 | 现在该不该开口、找谁、说什么更像人 |
| 会不会主动发消息 | **不会** | 会 |
| 数据流向 | 导出契约快照 | 读契约，写回信号 |

两个插件一起用时不需要额外配置：

- **Core → Social**：`state.json` 里每个角色的 `self.contract`，带 `v` 版本号，字段只加
  不改。里面是各条身体轴、第一人称体感短句、说话形式倾向（`max_chars`、提问倾向）、
  她那个城市的 UTC 偏移（`time.utc_offset_minutes` / `time.tz`），以及「她多想找人说话」
  这个量。社交层拿它当念头模型的燃料，而不是自己从精力标量硬猜。
- **Social → Core**：社交层往**自己**的目录里写一个 `humanoid_signals.json`（刚主动找过
  谁、被连着冷落几次）。Core 只读它，超过 15 分钟不采信。两边各写各的文件，不存在两个
  插件抢写同一个文件的问题。

**怎么确认到底对接上了没有**：`/拟人诊断`【身体与联动】那两行现在会把话说到底——
「读到并在用（上次刷新 Ns 前，看的是 <绝对路径>）」/「没装「自主拟人社交」插件，这不是故障」/
「装了但还没写过信号文件」/「文件在，但已经 N 分钟没刷新」。`/你的状态` 里也有一行
`- 自主拟人社交：…`。以前只有一句「没读到 humanoid_signals.json」，三种情况长得一样。

拿不到契约时（没装社交层、或 Core 太老没有 contract 段），社交层会退回读旧字段，功能
不中断。`/拟人诊断` 会明确告诉你联动到底有没有生效。

## 状态是怎么交给模型的

插件的职责是给 AI 一具身体：她的困、饿、攒着的火、今天过掉的那段日子、以及你面前这个人
在她心里的位置，都要真的被她感觉到。但**给的是事实，不是台词、不是禁令、不是读数，
也不是插件替她编的细节**。

### 分两处放

| 放哪儿 | 内容 | 为什么 |
|---|---|---|
| `system_prompt` | 一段 200 字的框架：这些是她的身体与处境，按人怎么理解自己就怎么理解 | 它不随消息变。塞进用户消息里，每说一句话就多存一份到聊天历史 |
| 用户消息后面 | 事实块（下面那些【】） | 每条消息都在变，必须新鲜 |

事实块开头是 `〔她的身体与生活 v4 uid=…〕`，每次注入前会把上下文里**旧的块抹掉**，
所以全程只有一份、且是此刻的。AstrBot 保存历史时跳过初始 system 消息，框架句不会滚雪球。

```
〔她的身体与生活 v4 uid=bot1〕
【此刻】私聊，只有你和TA；2026-08-22 15:20 下午；你在东京。
【感觉】有点犯困；这段时间她自己排的是觉。
【对TA】对TA的感觉：热情；跟TA挺熟，说话不用挑；这事你确实想知道下文；你管TA叫小鱼。
【刚刚】TA有 3 小时 12 分没吭声了；TA离开前说的是「我猫今天吐了」；这期间她在改海报。
【身边】手上在做的：跟客户过方案/先处理最紧要的一项。
【今天】今天到这会做过：上午在改第三季度的海报；傍晚还要通勤与买菜。
【记得】TA之前说过「我猫今天吐了，带去医院看了一下」。
```

七个要点：

1. **三样必需品每档都在**：时间（她的钟点、星期、节日）、场景（私聊还是群聊）、称呼。
   没记下称呼时整行不提：旧版那句「还没问过TA叫什么」会被模型当成待办，逢人就追问名字。
   现在没名字就只叫「TA」，名字由自动认定从消息带的名字里拿（见下）。
2. **给体感，不给数值。** `好感46.0/100`、`社交能量100%`、`UTC+08:00` 是给人核对的体检单，
   不进上下文。要看数值去 `/你的状态`、`/好感度`、`/时间`、`/拟人诊断`。
3. **间隔是经历，不是秒表。** 三段：TA那句原话 + 隔了多久（准确时长）+ **这期间她自己干了什么**。
   光给「3 小时 12 分」她不会有反应；给全这三段，「这人是不是去忙了」的念头是她自己生出来的。
4. **注意力是三条轴**（`/你的状态` 里能看到数值）：
   - `在意度`——对这个人。慢变量，每用户有自己的基线（不是所有人第一面都 50 分）。
   - `上心程度`——对 TA 正在讲的这件事。每条现算：问句、长度、是否推到她今天在忙的事、
     是否推到她记着的 TA 之前说过的话。
   - `注意力余量`——她自己手里还剩多少，跟 TA 无关。困、难受、在睡、手上正忙都会吃掉它。
   进上下文的是措辞（「这事你听进去了」/「这会儿你腾不出多少注意力」），不是百分比。
5. **措辞不是一份稿子。** 程度由轴值挑，同一档位备 2~3 套等价说法，按（角色 + 今天 + 用户）
   抽签：同一天不会把同一句话说两遍，隔天换人换一套。体感、心气、间隔、精力档位都走这一层。
6. **身体照算，只是不念出来。** `form_policy`（这一轮够得着多大份量）、各条轴、显著度门控
   全都还在算，并且通过联动契约给社交层用；**不进聊天上下文**。她在睡觉时被插件规定「只能说
   20 字」不是参考，是限制。
7. **不替她说话，也不给她立规矩。**
   - **台词与编造细节**：「你还在睡，是手机震醒的那种：眼睛睁不开，话到嘴边只剩一两个字」——
     手机、眼睛、脑子都不是算出来的，那是插件替她写的人设。现在夜间只有一句事实：
     「这段时间她自己排的是觉」。
   - **禁令**：「不要接着聊」「别超过60字」「这一轮不追问」——插件拦不住回复，这类句子只是让
     模型去猜规矩。
   - 这两条由测试卡着：`tests/test_v2151_freedom.py` 把身体推到极端（熟睡、饿、难受、被冷落）
     后渲染三档注入，逐项断言没有命令句、没有台词、没有读数、没有编造的身体细节，
     并且三样必需品每档都在。

## 升级（覆盖安装）

AstrBot 的「本地安装 zip」不会覆盖同名目录：装过旧版时直接上传会报
`安装失败：目录 astrbot_plugin_humanoid_core 已存在。`，插件列表里的「更新」也只会报
`该插件不是通过插件市场安装，无法检测或执行更新。`（上传安装的插件没有市场来源）。
升级二选一，两种都不丢身体状态：

1. 面板：插件 → 本插件 → 卸载（**不要勾**「删除配置」「删除数据」）→ 立即上传新 zip。
   配置在 `data/config/astrbot_plugin_humanoid_core_config.json`，身体与日程状态在
   `data/plugin_data/humanoid_core/state.json`，卸载只删 `data/plugins/<目录名>`，两个都不动。
2. 终端原地替换：先把新 zip 用「本地安装」上传一次（会失败，但包已落到
   `data/temp/plugin_upload_<原文件名>`），再解压覆盖 `data/plugins/astrbot_plugin_humanoid_core`，
   最后在面板点「重载」。

升级后第一次启动会看到日志里的配置默认值迁移提示：AstrBot 只补缺失键、从不覆盖已有值，
所以没手动改过、但停在旧版默认值上的项由插件自己提升一次。

| `/拟人诊断` | 模型链体检 + 时间与时区（地名→IANA→她的钟点→与机器时间差）+ 作息一致性 + 身体与联动状态 + Token 预算 |

## 日程是怎么来的（v2.15：按她是谁来排）

以前 prompt 开头是 `请为「温柔体贴」这个人设，规划今天一整天的生活日程`——一个插件里的
十二选一标签。形容词排不出一天：没有职业、没有住处、没有来往的人，于是日程永远是
「上午工作、中午午餐、下午工作」这种谁看了都不会信是自己过的东西。

现在直接读**她在 AstrBot 里生效的那份人格设定**（会话上指定的 → 该会话配置画像的默认 →
全局默认，解析链与正常聊天完全一致），让她是谁先立住，再排她的一天：

```
她是「林小满」。下面是她在 AstrBot 里的人格设定，这就是她本人，不是她在扮谁：
<人设原文，按行边界截到 1200 字>

先从这里读出她的身份、年纪感、职业或在读状态、住在哪里、独居还是跟人住、平时跟谁来往、
喜欢什么讨厌什么、花钱和精力的习惯。
设定里没写的，按最合理、最省心的方式补一个出来，然后每天都沿用同一个答案：这份日程每天都会重排，
但同一天里她不能今天在读大学、明天在上班。
```

表怎么填由模型自己决定：prompt 里只递三样东西——她是谁、她此刻的身体参考数值
（精力/饥饿/睡眠压力/睡眠债/昨晚睡了多久/生理周期，每次重排现取的活值，标明「是参考，
不是必须满足的条件」）、表格长什么样。每个时段做什么、多长、粒度多细，由模型结合人设
与身体状态自行权衡；v2.16.7 之前写在 prompt 里的那些内容提示（「要有真的会打断聊天的事」
「别排成每分钟都在做有意义的事」）全部删了——那是插件在替模型思考。

几个必须说清的点：

- **按角色隔离，插件里不放全局人格开关**。AstrBot 的 `unified_msg_origin` 第一段就是平台
  适配器实例，配置画像按 `platform_id::` 路由，所以按角色记账过的会话来源解析人格，天然
  就是按角色隔离的——一个机器人接多个人设、多个角色各用人设都自动正确。
- **代表会话从消息里记账**（`roles[bid].self.last_umo`），重启后也能立刻恢复。角色刚创建、
  还没收到过任何消息时取全局默认人格。
- **认出人设后会把今天重排一次**（每角色每人设每天最多一次）。不加这一手，插件刚装好那天
  的日程会一直停在「没见到人设」的版本上，要等到半夜跨天才对得上。
- `[%None]`（该会话显式不用人格）按「没有人设」处理，**不会**回退到默认人格——含义相反。
- 读不到人设时 prompt 走一段中性身份（「一个有自己生活的普通人」），日程照生成，不会因此
  停摆。想彻底关掉：`schedule_use_persona=false`。
- `schedule_prompt_extra` 保留，但它现在是**补充**而不是唯一依据。
- **作息也从人设里读**（v2.16.4）。prompt 里以前写的是「她的作息必须遵守：23:00 上床，
  生物钟夜到 6:00 结束」，那等于一个写死的窗口替所有人决定几点睡——夜猫子人格根本排不出
  来。现在是「几点睡、几点起由她是谁决定：从人设里读她的年纪感、工作或学业、生活习惯，
  结合当前的身体数值（困意、睡眠债）由你判断；人设里写着的作息保持不动」。她真排成凌晨
  4 点睡，身体就按凌晨 4 点算（见下面「作息」一节）。

日程不再一天只排一次：跨天立即排，平时每隔 `schedule_refresh_minutes`（默认 15 分钟，
与 15 分钟粒度对齐）就按她当时的身体数值重排一次当天日程。默认时段上限 96 = 24 小时 ×
4 格，模型可以逐格填也可以把连续几格合并成一个时段，但必须把 24 小时每一格都填满。
请求都在后台，聊天照常，期间用按日期确定性轮换的内置模板，拿到结果后自动替换。

候选链：`首选模型 → 备用模型 → 全局默认模型 → 内置日程模板`。找不到、超时、报错三种
失败等价处理；失败的模型进入冷却期（默认 30 分钟）内被跳过，成功一次立即解除；整条链
都失败则按退避间隔重试。**日程生成失败不会阻止第二天重新尝试。**

一个值得知道的细节：**失败退避以前会被永久绕过**——`today_date` 只在生成成功时写入，
模型一直不可用时它永远不是今天，于是每个后台周期都被当成「跨天」而绕过冷却，变成每
30 秒一次永久重试。v2.14 起会记住「今天试过」，退避真正生效；v2.16.7 又补了一刀：
「到点重排」也不绕过退避（模型挂掉时它永远判得到点，不挡会退回同样的永久重试），
只有用户 `/重置日程` 或跨天可以硬闯。

## 身体是怎么变的

日程里每个时段带一个 `energy_rate`（每分钟精力变化）。负值时段只减，非负时段才回升；
生理周期给消耗和恢复各乘一个阶段系数。此外：

- **睡眠债**压低新一天的精力起点（欠得越多起得越低，最低到 5 折）
- **躯体不适**放大消耗、并给精力设一个当天封顶——欠着一身债的人，就算日程写着整个
  下午都在休息也回不满
- **吃饭**由日程里的用餐时段决定，一顿就把饥饿归零
- **久坐**在日程写着运动/通勤/家务的时段会被打断
- **天气**的冷热计入躯体不适（需要天气可用）

想调曲线：`energy_decay_rate`（全局速度倍率）、`energy_natural_recovery_per_minute`
（休息时段的额外恢复）、`sleep_need_hours`、`meal_interval_hours`、
`sitting_discomfort_minutes`、`desire_refill_hours`。

## 作息：夜间窗口、日程、一晚睡多久

「她几点起」以前有三个地方都能回答，而它们互相不认识：夜间窗口说 5 点，日程模板说
7:30，`sleep_need_hours` 说 8 小时（而且根本没人读它）。v2.14.2 把三者接成一条链：

| 层 | 管什么 | 不管什么 |
|---|---|---|
| 今日日程的睡眠段 | **她的生物钟夜**：昼夜低谷摆在哪、睡眠债从几点开始记、窗口多长 | —— |
| `night_start_hour` → `night_end_hour` | 日程还没生成、或日程里没有睡眠段时的**兜底**窗口 | 不再反过来规定她几点睡 |
| `sleep_need_hours` | 一晚睡多久算睡饱：困意清除速率 = `100/本值` 每小时；窗口比它短时，熬一小时欠的债更多 | 不参与「她醒了没」的判定 |

**方向在 v2.16.4 掉过来了**：以前是日程被代码切到 `23:00→06:00` 那个窗口上（夜猫子人格根本
排不出来），现在是**身体跟着她的日程走**——`soma.biological_night()` 从今天日程里最长那段觉
（会自动合并 `23:30→24:00` + `00:00→07:00`）推出她的昼夜低谷与记账边界。凌晨 4 点睡、
11 点半起的人，低谷就跟着挪到 7 点半前后。

`schedule_follow_night_window` 默认**关**。打开它才是硬覆盖：日程 prompt 里写死她几点上床，
模型不听时安装前还会把睡眠区间按窗口重切一次。从没碰过作息设置的老用户会被一次性迁移到
新默认（真去改过夜间窗口的不碰）。

她的日程只排 5 小时而一晚需要 8 小时是**真的会出问题**：早上带着没清完的困意起床，下午就蔫。
`/拟人诊断` 的【作息】会直接标出来（它比的是她**实际排到的那段觉**，不是配置窗口）。

**夜间那条事实给不给**由 `show_sleep_window` 决定（默认给）：

| | 她在睡 | 夜里但没排睡眠 |
|---|---|---|
| 开（默认） | 这段时间她自己排的是觉 | 按她自己的节律，现在是这一天里最该睡的时候 |
| 关 | 不提这条事实（身体照算，社交层照样看得到她在睡） | 同左 |

旧版这里有两类句子被删掉了：一是「我现在需要休息，明天再聊吧」这种**插件替她把话说完**，
二是「是手机震醒的那种：眼睛睁不开，话到嘴边只剩一两个字」这种**插件替她编的身体细节**——
手机、眼睛、脑子都不是算出来的，那是人设。回不回、怎么回、说多长，从来是她自己的事。

`form_policy`（她此刻大概说多长、想不想问）照旧计算并写进联动契约——社交层的主动消息靠它
决定长度；它**不再进聊天上下文**，因为「这副身体只够说一两句」写着写着就成了限制。

## 上次对话间隔

`last_interaction_threshold_minutes` 默认 5 分钟：超过这个时间，插件才开始在上下文里
给间隔信息。算的是**上一次触发回复**到现在，所以纯指令消息和没唤醒它的群消息不会
重置计时。第一次对话没有历史，不会出现这段提示。

v2.16.4 起这块是**三段经历**，不是一句秒表读数：

```
【刚刚】TA有 3 小时 12 分没吭声了；TA离开前说的是「我先去开会了」；这期间她在改海报。
```

- **隔了多久**：准确时长（`3 小时 12 分`），措辞按天抽签（「TA上一条消息是…前发的」/
  「离TA上次说话过去…了」/「TA有…没吭声了」）。
- **TA那句原话**：`last_interaction_mode=with_last_msg`（默认）时附上。
- **这期间她做了什么**：从今天日程里落在间隔内、且已经结束的那些时段算出来；跟【今天】
  那块同源但不重复。间隔不足 30 分钟时不给这条。

「TA是不是去忙了」「该不会睡了一天吧」这种念头**不写进去**——那是她自己从这三段事实里
生出来的东西，插件替她想好就等于替她说话。旧版那句「这是一次性的背景，不是每天要重新
问候的事」也删了，它改住在框架句里只说一次。

间隔事件是**一次性**的：只在「回来这一轮」出现，下一条用户消息开始就清掉。

## 情绪是怎么算的

好感度、亲近欲、攻击性三个维度，每条消息先过一遍本地词典规则；开着
`mood_use_llm_for_delta`（默认开）时，每 `mood_llm_interval_messages` 条消息（默认 5）
再叫模型分析一次，两个结果加权融合。计数从 0 起算，所以新面孔的第一条消息只走本地规则。

- 精力与生理周期会调制情绪变化的幅度（排卵期更敏感，经期正负都被放大）
- 心情标签在每次情绪更新时刷新（`mood_tag_enabled`），显示在 `/情绪详情` 里
- 群聊默认不参与情绪：`mood_enabled_in_group` 关着时群消息不做情绪分析与衰减，但发言过
  的成员仍会记录聊天间隔与上一条消息（群聊里的「知道好久没聊了」靠它）
- 情绪模型的失败冷却与日程的冷却各自记账，即使两边用同一个模型也互不影响
- `mood_data_retention_days` 默认 7 天：超过 7 天没说话的用户，情绪档案会被清掉，好感度
  回到初始值；**用户自己设定的昵称保留**（自动认定的称呼和来路也保留）。设为 0 = 永不清理
- **称呼自动认定**（`auto_nickname`，默认开）：这个人还没有任何称呼时，从消息自带的名字认一次
  怎么叫 TA：群聊优先群名片（没名片才退回 QQ 昵称），私聊认 QQ 昵称。门槛很高——含任何数字
  （QQ 号、白开水123）、空格、下划线、emoji、【】（）★彡装饰、首尾标点的名片一律不认；单字与
  两个字母的缩写不认；已注销用户/管理员/游客/测试/N/A 那类占位词不认，宁缺勿错。只填空白不碰
  存量：认过之后换名片也不改口，用户 `/叫我` 设过的更碰不到；称呼一旦落库（含重启后），自动
  认定永远不会改动它——设置过一次就只有一次，唯一例外是用户自己重新 `/叫我`。落库时记下来源
  （用户自设 / 自动认定），`/查看所有昵称` 里看得见；自动认不上时她也不追问名字，只是不带称呼

## Token 预算

两个插件加起来一共只有 4 处会真的调用模型，全部量过（注入器自己渲染真 prompt，不拿常量猜）：

| 调用点 | 什么时候发生 | 实测单次消耗 |
|---|---|---|
| 聊天时追加的事实块 | 每次聊天请求 | 随当时的身体与日程浮动（轻载 ≈75–105，身体有事可说时 ≈130–200 token）；`/拟人诊断` 量的是此刻的真值 |
| 同上，框架句 | 每次聊天请求（进 system_prompt，不落历史） | ≈196 token，一段固定话 |
| 日程生成 | 每角色每天 1~2 次 | 输入 ≈570（无）～1320（带人设，截到 1200 字）+ 输出按 16 时段 ≈550 |
| 情绪分析 | 每 5 条私聊 1 次（可关） | ≈520（用户消息只取前 500 字） |
| 社交层写话/把关 | 每次准备主动开口 | 生产最坏 ≈2100（含人设 800 字 + 5 条历史）；输入预算卡在 6000 token，超了按固定优先级丢块 |

卡住上限的几道：

- 事实块按 `inject_token_budget`（默认 3500 token）卡总量：超了按显著度从低到高丢句，
  时间/称呼/场景这些必需品永不丢；丢的是整句，不留半句话给模型去补。
- 事实块每次注入前会先从上下文里抹掉旧的份（AstrBot 存的是拼装后的用户消息，不清就会
  越聊越多份过期身体状态），所以一次请求里只有一份、且是此刻的。
- 人设原文按行边界截到 1200 字再进日程 prompt；日程一天最多生成两次（认出新人设时重排一次），
  不会因人格反复变动而无限重跑。
- `schedule_prompt_extra` 是自由文本配置项，截到 300 字（以前无界，粘一篇设定就能把日程
  请求撑大）。
- 天气/情绪没配好时给管理员看的说明书不再进模型上下文，也不再写进联动契约（以前会漏
  一句「把 weather_location 填成英文名+国家码」）。**没拿到真天气时她不报天气**：
  以前没配 Key 也会得一句「晴朗 ☀️」，那是编的。
- 开 `debug_mode` 后，日志会直接打出本次注入的字符数与 token 估算。
- `/拟人诊断` 新增【Token 预算】段，用真状态量当前档实际多大，不是拿常量报数。

## 城市与时区：她按哪个钟过日子

`timezone_city` 不只是给 `/时间` 用的：她看到的钟点、日程里几点做什么、夜间窗口、睡眠债
从几点开始记、注入里那句「你在北京」、天气算不算得冷，全部按这个城市的当地时区算。

- **三个国家的地区全部收录**，共 9,855 条（v2.16.4 从 781 条补上来的）：
  - 中国：手写表 452 条（333 个地级 + 34 个省级 + 港澳台）打底，批量表把**县级及以上驻地**
    与人口 ≥2 万的地方全铺上（敦煌、满洲里、乌兰浩特、曲阜、阳朔、婺源、平遥、都江堰、
    井冈山都在）。
  - 日本：47 都道府县 + 县厅所在地 + **全部市町村**（札幌、川崎、箱根、轻井泽、八户…）。
    全国一个区时，所以能收的都收了。
  - 俄罗斯：85 个联邦主体名（裸名与官方写法都进表：`斯维尔德洛夫斯克州`、`萨哈林州`、
    `堪察加边疆区`、`印古什共和国`、`犹太自治州`）+ 全部首府 + 有中文名且人口 ≥1 万的居民点。
  - 表内条目都映射到真实存在的 IANA 时区名（测试逐项用 tzdata 加载一遍——名字不存在不会报错，
    只会让那个城市静默退回机器时间），夏令时由 IANA 数据自己处理。
- **地名怎么写都认得**：先精确匹配，再去掉行政后缀（市/区/县/省/府/都/盟/地区/自治州/
  自治区/特别行政区），最后才试前缀。所以 `广东省`、`大阪市`、`东京都`、`北海道`、
  `延边朝鲜族自治州`、`内蒙古自治区` 都能用。「州」与「道」故意不进后缀表：「北海道」剪成
  「北海」会匹到广西的北海市，那是跨国家错时区。重名有结论：`松江` 裸名归日本岛根县厅
  所在地（松江市），中国那个写 `松江区` 或 `上海松江`。
- **俄罗斯那一栏按 GeoNames RU.txt 的 PPLA/PPLA2 记录逐条重核过**：改掉 5 个走快一小时
  的城镇（滕达、涅留恩格里、阿尔丹、奥廖克明斯克属 `Asia/Yakutsk`，恰拉属 `Asia/Chita`——
  IANA 给 `Asia/Khandyga` 的注释只有 Tomponsky 与 Ust-Maysky 两个区），并补上比利比诺
  （`Asia/Anadyr`）、希姆基、沃洛格达、大诺夫哥罗德、普斯科夫。联邦主体的时区一律按**首府**
  给（萨哈共和国跨 3 个区，取雅库茨克那个）。
- **繁体与日文写法自动转一层简体别名**：`盛岡`/`盛冈`、`軽井沢`/`轻井泽`、`摩爾曼斯克`/
  `摩尔曼斯克` 两种写法都认。
- **中文显示名填得回去**：她说「你在雷克雅未克」，你把「雷克雅未克」填进配置就生效。
  以前这些名字只在显示表里、不在解析表里，填回去会静默退回机器时间。
- **跨国重名有结论**：白山、中山、松江、海南这类中日俄都有的名字，留人口多的那个；
  俄罗斯内部同名跨两个时区的**整条丢掉**——宁可认不出并明说，也不给一个错钟点。
- **表里没有的地方直接填 IANA 时区名**：`Asia/Ho_Chi_Minh`、`America/New_York`、
  `Europe/Berlin` 都能用。她说出来的是中文地名（「你在伏尔加格勒」），不是
  `Europe/Volgograd` 这种代码；填 `广东省` 就是「你在广东」。
- **中国大陆（含新疆、西藏）统一按北京时间**：铁路、电视、手机都走北京时间，这是法定时区；
  真想让她按当地 UTC+6 过日子，把 `timezone_city` 填成 `Asia/Urumqi` 即可。
- **填错与缺库分开报**：名字拼错时说「这个时区名用不了（可能拼错了）」，机器缺 tzdata 时
  才说「装一份时区数据库」——两种情况的改法完全不同。
- **不再静默退化**。旧版在机器缺 tzdata 时会偷偷换成 `Asia/Shanghai`：设成东京的她其实
  按北京时间过一天，而注入里还写着「你在东京」，从聊天记录里根本看不出来。现在退化成
  AstrBot 这台机器的本地时间，并把原因说出来。
- **换城市会把旧账重新起算**。精力与天气的「上次更新」在 state.json 里存的是墙上时间，
  换个城市再拿新时区解释就会凭空多出几小时。现在角色创建时发现城市变了，就把这两项按
  新城市重新起算（日志里会说一句）。
- **去哪看有没有真生效**：`/拟人诊断` 的【时间与时区】给出地名 → 生效 IANA 名 → 她此刻
  的钟点，再与机器时间对比（差几个小时是预期的，一致而她在另一个国家就是不预期）；
  认不出地名、缺 tzdata、城市还没定这三种情况都会带 ⚠ 与改法。`/时间` 的输出带
  `UTC±HH:MM` 偏移，一眼能对上——偏移只出现在这两个地方，不进她的上下文。

## 获取天气 OpenWeather 密钥

1. 访问 [OpenWeather](https://openweathermap.org/) 注册账号
2. 在 API Keys 页面生成免费密钥：https://home.openweathermap.org/api_keys
3. 将密钥填入配置项 `weather_api_key`
4. 把 `weather_location` 填成城市英文名加国家代码（如 `Beijing,CN`），或者留空让它
   跟随 `timezone_city`——但那样 `timezone_city` 本身就得是英文名
