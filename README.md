# Humanoid Core - 拟真生活状态引擎

一个有自己的时间、会累会恢复、情绪会积累的 AI 生活引擎。

---

## 它是什么

- 每天有不一样的日程安排，由大模型生成；生成在后台进行，不会拖慢聊天回复
- 精力随活动消耗与恢复：工作/外出时段只减不加，睡眠与休息时段才回升
- 有生理周期（6 个阶段，描述只提能量水平，不提具体症状）
- 情绪随对话变化：好感度、亲近欲、攻击性三个维度，各自有基线与衰减
- 会记住让它情绪波动的时刻（情绪日志）
- 天气会成为它日常状态的一部分（接入 OpenWeather）
- 知道今天是星期几、知道你所在城市的当前时间、知道今天是什么节日
- 你可以设定它对你的称呼
- 心情标签（如「疲惫但开心」），直观显示当前情绪
- 社交能量：每条消息消耗，长时间不聊天恢复，影响回复热情
- 夜间睡眠模式：分深睡 / 浅睡两段，深夜回复变短，或主动提示休息
- 知道你上次找它是多久以前
- 三档注入程度，控制它「知道你多少状态」
- 私聊 / 群聊 / 全开都行，它会根据场景调整语气

## 日程是怎么来的

每天第一次需要日程时，插件在**后台**向模型请求一份当天安排；请求期间聊天照常，
用的是按日期确定性轮换的内置模板，拿到结果后自动替换。所以模型再慢也不会让你的
消息卡住。

模型按候选链依次尝试：

```
首选模型 (schedule_provider_name)
   ├─ 未找到 / 调用超时 / 调用报错 ──┐
                                     ▼
备用模型 (schedule_fallback_provider_name)
   ├─ 同样三种失败 ──────────────────┐
                                     ▼
全局默认模型 (schedule_allow_global_fallback 控制，默认开启)
   └─ 失败 ──────────────────────────┐
                                     ▼
内置日程模板（按日期轮换，永远可用）
```

几个行为值得知道：

- **三种失败等价**：找不到、超时、报错都会切下一个候选，不区别对待。
- **失败冷却**：失败的模型进入冷却期（默认 30 分钟）内被跳过，不会每次生成都白等
  一轮超时。成功一次立即解除。`/重置日程` 会绕过冷却。
- **失败退避**：整条链都失败后，至少隔一段时间才自动重试，避免持续不可用时反复空转。
- **日程永不缺失**：所有候选都失败就用内置模板，其余功能不受影响。

配错模型 ID 时不用猜：日志会直接打出「你填的是 X，当前可用 id: [A, B, C]」，
或者直接 `/拟人诊断`。下拉框存的是 Provider ID，手填时注意大小写与下划线。

## 精力是怎么变的

日程里每个时段带一个 `energy_rate`（每分钟精力变化）。负值时段（工作、外出、社交）
只消耗；非负时段（睡眠、午休、休闲）才回升，自然恢复也只在这些时段生效。
生理周期会给消耗和恢复各自乘一个阶段系数。跨天时精力重置到 80 上下。

想让曲线更陡或更平，调 `energy_decay_rate`（全局速度倍率）和
`energy_natural_recovery_per_minute`（休息时段的额外恢复速度）。后者默认 0.15/分钟，
睡满一夜基本回满；想要更明显的日内起伏就降到 0.05~0.1，想睡一会儿就回满则调到 0.3 以上。

## 夜间模式

夜间窗口默认 23:00–06:00（`night_start_hour` / `night_end_hour`），按
`night_deep_sleep_ratio`（默认 0.5）从窗口开头切出一段深度睡眠，剩下的是浅睡/半醒。
默认配置下深睡大致覆盖 23 点到凌晨 2 点，之后是浅睡。

`night_mode_force_sleep` 决定强度，开启后更严格：

| | 关（默认） | 开 |
|---|---|---|
| 深睡段 | 极简短、迷糊、断续，像刚被吵醒，≤20 字 | 只回一句「我现在需要休息，明天再聊吧」 |
| 浅睡段 | 迷糊、慵懒，≤30 字 | 简短回应并提一句想睡了，≤30 字 |

这些都是写进 system_prompt 的语气指导 —— 插件不会拦下你的消息，最终怎么回还是模型决定。

### 上次对话间隔

> **v2.12.5 改进**：时间间隔不再以“已过去 X 分钟/小时”形式注入，而是根据间隔时长和好感度生成拟人化氛围描述（如“仿佛刚才还在聊”“心里空了一小块”），并明确禁止模型直接提及具体时间数据，使对话更自然、不机械。
`last_interaction_threshold_minutes` 默认 **5 分钟**：超过这个时间，插件才开始在提示词里注入间隔信息。

有两种模式可选（`last_interaction_mode`）：

| 模式 | 行为 |
|---|---|
| `simple` | 根据间隔时长和好感度生成拟人化氛围描述（如“心里空了一小块”“像隔了一个黄昏”），不直接提及具体分钟数 |
| `with_last_msg` | 同上，并附带用户上次最后说的话，**注入后自动清空（推荐选这个）** |

算的是**上一次触发回复**到现在，所以纯指令消息和没唤醒它的群消息不会重置这个计时。第一次对话没有历史，不会出现这段提示。

## v2.12.5：自然行为与时间间隔增强

v2.12.5 在保留原有拟真生活状态系统的基础上，进一步整理了 AI 的自然行为上下文。此次升级不改变原有配置结构，也不要求新增模型。

- **时间间隔事件**：根据用户离开时间形成不同强度的短期事件，例如短暂回来、隔了一会儿回来、隔了几小时回来或长时间重新出现。
- **注意力机制**：事件会按照重要程度与新鲜度进入当前上下文，避免所有历史事件同时干扰模型。
- **行为倾向**：结合精力、社交能量、好感度和近期事件，形成主动性、好奇心、关心程度、社交意愿与话题延续倾向。
- **自然决定而非固定台词**：插件只提供内部行为背景，不规定“必须问什么”或“必须说什么”，最终由模型结合当前对话决定是否表达。
- **上一句话衔接**：`with_last_msg` 模式下，可以提供用户离开前最后一句话，使重新开始对话时更容易自然接上原话题。
- **角色与用户隔离**：行为事件按角色和用户独立保存于运行时上下文，不会把一个分身的行为状态混到另一个分身。
- **稳定性优先**：行为事件属于短期运行时信息，不额外扩大长期状态文件；原有时间、生理、情绪、社交、日程、天气和过程系统继续按原逻辑工作。

这套机制的目标不是让插件替 AI “演戏”，而是给模型提供类似“刚发生了什么、现在更在意什么、倾向于怎么回应”的背景，让拟人化表现由模型自然完成。

## 情绪是怎么算的

好感度、亲近欲、攻击性三个维度，每条消息先过一遍本地词典规则；开着
`mood_use_llm_for_delta`（默认开）时，每 `mood_llm_interval_messages` 条消息（默认 5）
再叫模型分析一次，两个结果加权融合。计数从 0 起算，所以新面孔的第一条消息只走本地规则，
不为建档花一次模型调用。

- 群聊默认不参与情绪：`mood_enabled_in_group` 关着时群消息完全不碰情绪系统，不分析、
  不衰减、也不给群成员建档。
- 情绪模型的失败冷却（`mood_provider_cooldown_minutes`，默认 5 分钟）与日程的冷却
  （默认 30 分钟）各自记账，即使两边用同一个模型也互不影响。
- `mood_data_retention_days` 默认 7 天：**超过 7 天没说话的用户，好感度会被清回初始值。**
  不希望它忘掉老朋友就把这项设为 0。

## 新增配置项
- `process_min_duration`：过程最小持续时间（默认15分钟）
- `process_max_duration`：过程最大持续时间（默认90分钟）
- `process_auto_update`：是否自动更新过期过程（默认true）
- `process_history_limit`：过程历史保留条数（默认5条）

过程现在采用“过程主题 + 过程阶段”的结构：主题负责维持一段时间的生活连续性，阶段负责在过程中产生自然的小变化。过程只是角色状态背景，不是对模型发言的限制。

## 代码结构

```
main.py                  # AstrBot 适配层：指令注册 + 事件解包 + HTTP 注入
humanoid/
  config.py              # 唯一的默认值来源 + 类型强制 + 范围钳制
  state.py               # StateStore：异步锁 + 去抖原子写 + 字段迁移
  clock.py               # 时区 / 当前时间 / 星期 / 节日
  llm.py                 # ProviderResolver + LLMGateway（回退链 + 冷却熔断）
  slots.py               # 日程时段的解析与规范化流水线
  jsonx.py               # 从模型回复里抠 JSON
  prompt.py              # 注入文本构建
  diagnostics.py         # /拟人诊断 报告
  engine.py              # 编排层：服务装配 + 后台任务 + 指令文本
  services/              # schedule / energy / mood / social / weather
  data/                  # 城市时区表 / 节日 / 情绪映射 / 日程模板
tests/                   # 纯 stdlib unittest，不引入运行时依赖
```

`humanoid/` 子包不 import 任何 astrbot 模块，框架对象一律注入，所以整套业务逻辑
可以脱离 AstrBot 单测。被 `@filter` 装饰的处理器必须留在 `main.py`——AstrBot 按
`handler.__module__` 查 `star_map`，放到子模块里会注册不上。

跑测试（在插件根目录）：

```bash
python -m unittest discover -s tests -t .
```

201项，其中 24 项是 `main.py` 的集成测试，本机没装 AstrBot 时会自动跳过。

## 自然行为与时间间隔感知

插件除了提供时间、生理、情绪、过程、社交能量和天气等基础拟人状态外，还包含一个轻量的**行为与注意力层**。

它的作用不是替 AI 写固定台词，而是把“刚刚发生了什么”整理成模型能够理解的上下文：

- **对话间隔感知**：能够识别约 5 分钟、30 分钟、2 小时、6 小时以上等不同程度的离开与回来。
- **事件化处理**：时间间隔会形成短期事件，例如“对话恢复”“用户回来”“较长时间后回来”等。
- **注意力机制**：事件会随时间自然衰减，避免旧事件长期影响模型。
- **行为倾向**：根据事件、精力、社交能量和关系状态形成“主动性、好奇、关心、社交意愿、话题延续”等倾向。
- **不强制说话**：行为倾向只是模型的决策背景，不会要求 AI 必须提问、必须撒娇或必须提及时间间隔。最终由模型结合当前对话自然决定。
- **上一条消息关联**：启用 `with_last_msg` 时，较长间隔事件可以携带用户离开前的最后一句话，让模型更容易自然接上之前的话题。
- **角色与用户隔离**：行为事件按角色和用户独立保存，不会把不同分身之间的短期行为状态混在一起。
- **不污染持久状态**：短期行为事件仅在运行时存在，核心持久状态仍由原有状态系统负责。

### 设计原则

整体行为链路为：

`持久状态 → 新事件 → 注意力 → 行为倾向 → Prompt 上下文 → LLM 自然决定回复`

因此插件负责提供**状态和行为背景**，而不是代替模型编写回复。这样既能增加拟人感，也能避免“每隔两个小时就机械地问一次你去哪了”这类明显的脚本感。

原有功能和配置保持兼容，行为层没有新增必须填写的配置项。
